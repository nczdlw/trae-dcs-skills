# 越南 F163 莱歇磨 AI 编程按系统复核报告

复核日期：2026-07-28  
复核对象：`outputs/f163_loesche_programming`  
结论等级：**不具备直接导入、完整 Check 或下装条件**

## 1. 复核结论

本次按 G10、G20、G30、G40、G50、G55、G58、G60、G62、G65、G71、P98、P101 共 13 个系统，对照莱歇正式联锁图、启停顺序、最新版设备清单和仪表清单进行了交叉检查。

当前交付物不是“13 组全部通过”，存在会导致导入失败、编译失败、设备归属错误或工艺功能缺失的问题。最关键的结论如下：

1. `NEW_CEMENT.VAR.xlsx` 实际有 858 条变量记录，但只有 821 个唯一变量名，存在 **37 个重复变量名**。原汇总报告把“821 个唯一名称”写成“821 个变量且全部通过”，结论不成立。
2. G50、G55、G65 等系统存在明确的数据类型错误，包括把 TON 实例、TIME 参数、状态机状态、REAL 流量设定值声明为 `bool`，无法按现有 ST 代码通过类型检查。
3. G58 把现有选粉机 `1652CL01` 误解释为“破碎机”，G62 又新建了一套选粉机变量和逻辑，造成同一物理设备重复编程；同时 G62 在现场基线中原本标识为齿轮箱组。
4. G65 喷水流量公式漏除 `1000.0`，正式图要求把 `l/h` 换算为 `m³/h`；当前算法会产生 **1000 倍量纲错误**。低流量阈值暂设为 `10.0 m³/h`，也高于仪表清单所列 `0.8～8 m³/h` 量程上限。
5. G71 仅实现组允许和四选一锁存，却在代码中声称“无模拟量、无 DI、无变频”。正式资料明确包含流量 FI01、PID、变频泵、补液泵、4 个罐、12 个液位点、8 个阀位反馈、8 个电磁阀和 2 个调节阀，绝大部分功能遗漏。
6. 多个 HTML 文件只是 FBD 管脚连接说明，并不是已导入 Control Builder 的 FBD 实现；多个 VAR/FUN 增量表为空、格式不符合主表或缺少实际功能块实例。
7. 尚未取得 ABB Control Builder 完整 Check 结果。交付物自身也仍标注“待粘贴”“待现场验证”“待配置 CI860”等事项，因此不能认定已完成。

## 3. 总体导入与编译阻断项

### P0-01 主 VAR 表名称不唯一

`NEW_CEMENT.VAR.xlsx` 的使用区域为 `A1:I860`，扣除标题和表头后为 858 条数据；其中有 37 个名称各重复一次，因此只有 821 个唯一名称。ABB 程序变量名必须唯一，不能把当前文件作为已通过的完整导入表。

### P0-02 明确的数据类型错误

下列类型与 ST 使用方式不一致：

| 变量 | 当前类型 | 实际用途/应核对类型 |
|---|---:|---|
| `G50_TON_BUILD`、`G50_TON_LIFT` | bool | TON 实例 |
| `G55_TON_BUILD`、`G55_TON_LIFT` | bool | TON 实例 |
| `G55_PT_BUILD`、`G55_PT_LIFT` | bool | TIME |
| `G55_STATE` | bool | CASE 状态，至少应为整数类型 |
| `N562_WI5_FLOW_SP` | bool | REAL 流量设定 |
| `N562_WI5_S09_SP` | bool | REAL 速度/流量设定 |
| `N562_WI5_CLEAN_CNT` | bool | CTU 计数值/整数 |
| `N562_WI5_F01` | bool | 流量模拟量，REAL |

此外，至少 16 个声明为 `bool` 的变量在代码中被当作结构体使用 `.Value`，例如：

`N562_HD1_L1`、`N562_HD1_P1`、`N562_HD1_T1`、`N562_HD2_L1`、`N562_HD2_P61`、`N562_HD2_P71`、`N562_HD2_T1`、`N562_LQ3_L1`、`N562_LQ3_T1`、`N562_FN4_P1`、`N562_RM1_G1`～`G4`、`N562_WI5_LS03`、`N562_WI5_LS04`。

标量 `bool` 没有 `.Value` 成员；必须在“改为正确功能块/结构类型”和“删除 `.Value`、直接使用 BOOL”之间统一，不能维持现状。

### P0-03 未声明或未进入主表的引用

静态交叉检查发现以下 ST 引用未在当前完整 VAR 表中找到：

- G20：`N562_HD1_E01_O2`、`N562_HD2_E01_O2`、`N562_LQ3_E01_O2`、`N562_LQ1_E01_O2`、`N562_LQ1_T49`；
- G30：`N562_LQ1_T01_T_HH`。

如果这些点属于 Application 或硬件全局变量，仍需提供正式访问变量声明并验证作用域；目前不能据此认定代码可编译。

### P0-04 FUN 表和分组增量表不可靠

- 完整 FUN 表第 111 条为实例名 `NOT`、类型 `NOT`。`NOT` 是 ST 运算符，不是本项目已证实存在的自定义功能块类型。
- G50 的独立 FUN 表又把实例 `NOT` 声明为 `SMOTOR_PROV`，与完整 FUN 表互相矛盾。
- G55、G58、G62、G65、G71、P98、P101 等多份 FUN 文件为空或仅有表头。
- G62、G65、G71 的正式设备功能块没有进入完整 FUN 表；只有组壳或说明文档。
- 多份分组 VAR 表只有 6 列：`No./Name/Data Type/Initial Value/Comment/Attributes`，与完整 ABB VAR 表的 9 列结构不一致，不能直接作为同格式增量导入文件。

### P0-05 FBD 尚未实际实施

FBD HTML 文件给出的是人工接线指南。它们不能证明 Control Builder 工程中已经存在功能块实例、管脚连接、任务连接和硬件访问变量。当前交付物还明确要求后续“配置 FBD 管脚”“配置 CI860”“完整 Check”，所以“跨组信号已全链路闭环”的结论没有工程证据支持。

## 5. 重点系统证据

### 5.1 G10：反馈状态被命令状态替代

联锁图第 99 页明确要求 AUX_RUN 由以下真实状态组合：

- `1632LQ01:RUN`；
- `1632LQ10:ENABLED`；
- `1632HS10:RUN`；
- `1632HS20:RUN`。

但 `G10ST.st` 中：

- `G50_RUN := G50_CMD`；
- `G55_RUN := G55_CMD`。

联锁图第 159、189 页显示 HSLM/HSSW 的 `RUN` 来自 Group 的 `FBON`，并不等同于命令或 `ENABLED`。现逻辑可能在泵和阀尚未建立真实反馈时提前产生 AUX_RUN。

同时，代码用：

- `N562_RMF_ON := G60_RN AND NOT PQSTOP`；
- `N562_MAT_IN_MILL := N562_RMF_ON`。

替代设计院范围的 RMF 真实组状态和“物料入磨”信号。该代理不能作为正式运行逻辑，否则 G65/G71 会在没有真实喂料时错误投入。

### 5.2 G30：正式投票逻辑被改成简单 OR

联锁图第 134～140 页包含：

- 相邻瓦组合；
- 随机数量组合；
- 两相邻组合；
- 2 s、3 s、10 s 等延时；
- `HP_MON_1`、`HP_MON_2`、`HP_MON_3`、`HP_MON_4_01/02/03/04`。

G30 代码明确写成“本项目采用简单 1oo15 OR、无延时”。这不是更换表示方式，而是改变正式因果矩阵，会造成任何一个低压点立即触发整组保护，与正式功能不一致。

### 5.3 G58/G62：选粉机重复且归属错误

现场完整 FUN 基线已经定义：

- `N562SR1`：`1652CL01/Cement Mill Classifier (VFD)`；
- `N562LQ2M01`：`1652LQ51.MT01/Auxiliary lubrication oil pump`；
- `N562SR1S1`：`1652CL01.SI01/Classifier rotor speed`；
- `N562LQ2P1`：`1652LQ51.PI01/oil pressure`；
- `N562FN4`：`1632FN01/Cement Mill Seal Air Fan`。

联锁图第 234 页是密封风机，第 235～245 页是选粉机减速机润滑和选粉机。G58 的现有设备网络正对应这些对象，不存在代码所称的“破碎机 1632SR1”。

因此应先修正 G58 的设备解释和联锁，不应再在 G62 新建第二套选粉机。

### 5.4 G65：流量量纲和设定值错误

联锁图第 277 页的正式计算链为：

`TOTAL_FEED_SP [t/h] × RATIO_WATER_PER_FEED [l/t] ÷ 1000.0 = SPext [m³/h]`

代码当前为：

`FLOW_SP := RATIO_WATER_PER_FEED * TOTAL_FEED_SP`

少了 `/1000.0`。例如 100 t/h、1 l/t 时，正式结果应为 0.1 m³/h，代码却给出 100，误差 1000 倍。

仪表清单第 15 页列出的 FI01 量程为 0.8～8 m³/h，而代码把低流量阈值设为 10.0；在整个量程内都会满足“低于 10”的条件，泵运行后会持续产生低流量报警/联锁。

### 5.5 G71：正式功能几乎未实现

联锁图第 280～299 页和最新设备/仪表清单共同确认至少包括：

- 主泵 `MT01` 和补液泵 `MT11`；
- `FI01` 流量测量和低流量报警；
- 4 个罐、每罐 3 个液位点，共 12 个液位信号；
- 每罐进/出口阀位反馈，共 8 个反馈；
- `SO11/SO12`、`SO21/SO22`、`SO31/SO32`、`SO41/SO42` 共 8 个电磁阀；
- 4 种混合选择、密度、助磨剂/喂料比例、水/助磨剂比例；
- 总喂料设定参与计算；
- PID 和变频泵速度设定；
- `VA61`、`VA71` 两只调节阀及 `GI61/62/71/72` 位置反馈。

当前 G71 ST 未实现上述主体功能，不能标记为“完成”。

## 6. 原汇总报告中的不成立结论

以下表述与实际文件不符，应撤销或改为“待整改后验证”：

- “13 个组全部通过”；
- “19 项遗漏已全部补齐”；
- “主 VAR 表 821 变量全部声明”；
- “主 FUN 表 120 功能块全部完成”；
- “跨组信号全链路闭环无断链”；
- “PQSTOP 四路来源、执行延时、四方影响全部实现”。

实际情况是：

- 821 是去重后的唯一名称数，原表仍有 858 条记录和 37 个重复名；
- 120 条 FUN 中包含异常 `NOT/NOT`，且 G62/G65/G71 的设备实例明显缺失；
- G10 的 RMF/MAT_IN_MILL 是代理信号；
- G71 主体功能未编程；
- 多个系统不能通过静态类型检查，更没有 Control Builder 完整 Check 结果。

## 7. 整改顺序

建议严格按以下顺序处理：

1. **冻结正式基线**：以现场最新 AFW 导出为唯一底稿，保留原组号、对象实例和硬件访问变量。
2. **先修 VAR/FUN**：删除 37 个重复名，纠正 TON/TIME/INT/REAL/BOOL/结构体类型，删除异常 `NOT` 实例，生成唯一、可导入的完整表。
3. **纠正 G58/G62 架构**：确认 G62 的原齿轮箱用途；把选粉机逻辑落回现有 G58 设备网络，禁止重复实例。
4. **重做 G65、G71**：严格按第 274～299 页逐页实现泵、阀、液位、流量、PID、定时和反馈。
5. **修正 G10/G30/G40/P101**：恢复真实反馈、正式投票/延时、L1 启动条件及独立 VI01/VS02 信号。
6. **完成外部接口**：接入 GC_RUN、RJ_RUN、RMF_ON/OFF、MAT_IN_MILL、PRO_DATA_OK、磨机风机保护和 CI860/REF615。
7. **参数审批**：所有“典型值”“暂设值”必须进入单独参数确认表，由莱歇、机械、电气和工艺负责人批准。
8. **工程验证**：在 Control Builder M 中依次执行导入、完整 Check、离线仿真、I/O 强制测试、启停顺序测试、故障注入和 PQSTOP 因果测试；完整 Check 为零错误后才可进入下载评审。
