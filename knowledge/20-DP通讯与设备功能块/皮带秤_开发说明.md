# 皮带秤功能块开发说明

> 越南 F163 粉磨站 - INTECONT Tersus 皮带秤
> 用通俗的语言解释整个开发过程

---

## 一、这是什么设备？

申克（Schenck）INTECONT Tersus 是一台皮带秤控制器，安装在水泥粉磨站的配料/计量皮带上。它通过 PROFIBUS DP 通讯与 ABB 800XA DCS 系统连接。

简单来说，这台设备的功能是：
- **称重**：测量皮带上物料的流量和累积量
- **控制**：接收 DCS 的启动/停止/设定流量等命令，控制给料机运行
- **报警**：检测流量超限、负荷异常等状况，通知 DCS

## 二、我们要做什么？

在 ABB 800XA Control Builder 中开发一个**功能块（Function Block）**，让它充当 DCS 和皮带秤之间的"翻译官"：

```
DCS操作员 → 800XA功能块 → PROFIBUS DP → 皮带秤控制器
皮带秤控制器 → PROFIBUS DP → 800XA功能块 → DCS操作员画面
```

功能块做的事情就是：
1. **读取**皮带秤的状态（运行/停止/报警/流量/累积量等）
2. **发送**DCS的命令（启动/停止/复位/设定流量等）
3. **处理**信号滤波、事件记录、报警生成

## 三、通讯数据是怎么传的？

皮带秤控制器和 DCS 之间通过 PROFIBUS DP 通讯，使用的是 FIXED_8_8 模块：
- **输出**（DCS → 皮带秤）：32 字节 = 8 个 4 字节的数据
- **输入**（皮带秤 → DCS）：32 字节 = 8 个 4 字节的数据

每个 4 字节数据要么是**位打包字**（32 个开关量塞进一个数），要么是**浮点数**（流量、累积量等）。

### 数据分布

```
DCS → 皮带秤（输出 32 字节）:
  字0-1: 预留        字6-7: 控制字2（标定命令等）
  字2-3: 预留        字8-9: 流量设定值（配料秤用）
  字4-5: 控制字1    字10-15: 预留

皮带秤 → DCS（输入 32 字节）:
  字0-1: 预留        字8-11: 状态字2（极限值报警）
  字2-3: 状态字1    字12-15: 实际流量（kg/h）
  字4-5: 状态字2    字16-19: 累积量1（kg）
                      字20-23: 皮带负荷（kg/m）
                      字24-27: 皮带速度（m/s）
                      字28-31: 累积量2（kg）
```

## 四、开发中最关键的发现

### 4.1 数据类型问题

800XA 中有两大类数据类型：
- **普通类型**：DInt、Real、Bool、Time、String — 可以在 ST 代码中随意使用
- **I/O 类型**：DintIO、RealIO、DwordIO — 是硬件通道类型，**只能通过 `.Value` 属性访问**

GSD 文件导入时，32 位数据只能转成 DintIO 或 RealIO。这些 I/O 类型在 ST 代码中不能直接赋值，必须用 `.Value` 属性：

```st
(* 错误：直接赋值会报 Type mismatch *)
in_status1_int := dpIn_Status1 ;           ← 报错！

(* 正确：通过 .Value 属性 *)
in_status1_int := dpIn_Status1.Value ;    ← 正确！
```

### 4.2 位打包和解包

皮带秤的控制字和状态字都是 32 位的"打包数据"，每一位代表一个开关量信号。

**解包（读取状态字）**：用除法和取余运算逐位提取

```st
(* 比如状态字1的第0位是"运行"信号 *)
Running := (in_status1_int MOD 2) = 1 ;         (* 第0位: 除以2取余数 *)

(* 第5位是"重报警" *)
Heavy_Alarm := ((in_status1_int / 32) MOD 2) = 1 ;  (* 先除以32，再取余 *)
```

**打包（构建控制字）**：用 IF 判断 + 累加

```st
out_ctrl1_int := 0 ;                    (* 从0开始 *)
IF TP_Start.Q THEN                       (* 如果要启动 *)
    out_ctrl1_int := out_ctrl1_int + 1 ;  (* 把第0位设为1 *)
END_IF ;
out_ctrl1_int := out_ctrl1_int + 8 ;    (* 释放位始终设为1 *)
```

### 4.3 释放位必须始终为 1

控制字1的第3位是"释放"信号，必须始终设置为 1，否则设备无法接收任何命令。代码中直接 `+ 8`（2 的 3 次方）。

### 4.4 Bit 31 的特殊处理

DInt 的最大值是 2^31-1 = 2147483647。要设置第 31 位（值为 2^31），不能直接加，否则会溢出。用减法绕过：

```st
out_ctrl1_int := out_ctrl1_int - 2147483647 - 1 ;  (* 等价于加 2^31 *)
```

## 五、文件体系说明

开发一个功能块需要 5 个文件（不走 STRUCT 路线）：

| 文件 | 比喻 | 内容 |
|---|---|---|
| **Par 表** | "对外接口" | DCS 和功能块之间的所有参数：命令输入、状态输出、DP 通讯数据 |
| **Var 表** | "内部记事本" | 功能块自己用的中间变量：解包用的 DInt 临时变量、报警消息字符串、定时器参数 |
| **Fun 表** | "工具箱清单" | 声明要用的功能块实例：定时器、报警器、事件检测器 |
| **Ext 表** | "空盒子" | 留空，不用填 |
| **Code.st** | "操作手册" | ST 代码：读数据→滤波→打包命令→写数据→报警 |

## 六、ST 代码的 10 个部分

代码按功能分为 10 个部分，按顺序执行：

```
Part 1: 读取输入 ← 把硬件数据读到变量里
Part 2: 信号滤波 ← 过滤掉短于1秒的抖动
Part 3: 命令脉冲 ← 把按钮命令变成1秒脉冲
Part 4: 打包控制字1 ← 启动/停止/复位/批量等命令
Part 5: 打包控制字2 ← 标定/去皮/调零等命令
Part 6: 写流量设定 ← 配料秤用
Part 7: 清零备用字 ← 保持干净
Part 8: 事件记录 ← 记录启动/停止/报警等事件
Part 9: 报警生成 ← 重报警/警告/未释放
Part 10: 状态缓存 ← 保存本周期运行状态，供下周期的停止事件检测用
```

## 七、配料秤和皮带计量秤的区别

两种秤共用同一个功能块，区别只有一个：
- **配料秤**：连接 `Flow_Setpoint` 参数，DCS 可以设定流量
- **皮带计量秤**：不连接 `Flow_Setpoint` 参数，只计量不控制

## 八、导入步骤

1. 在 Control Builder 中创建新的 Function Block Type
2. 导入 Var 表（18 个内部变量）
3. 导入 Par 表（56 个外部参数）
4. 导入 Fun 表（14 个功能块实例）
5. 粘贴 ST 代码
6. 编译，解决所有错误
7. 在硬件配置中，将 Par 表的 DintIO/RealIO 参数连接到 DP 从站的 I/O 通道

## 九、调试建议

1. **先看通讯**：确认 DP 从站在线，I/O 数据有变化
2. **再看状态字**：在在线模式下监视 `dpIn_Status1.Value`，确认数值在变化
3. **验证解包**：对照设备面板上的运行指示灯，确认 `Running` 变量跟随
4. **测试命令**：在 DCS 上发启动命令，观察 `dpOut_Ctrl1.Value` 的第0位是否变为1
5. **检查释放位**：确认 `dpOut_Ctrl1.Value` 的第3位始终为1（值为8的倍数）
