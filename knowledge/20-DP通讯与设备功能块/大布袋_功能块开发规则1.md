# ABB 800XA Profibus-DP 功能块开发规则

> 基于 KDMC2880 除尘器功能块开发实践总结，适用于 ABB 800XA 6.1.0 Control Builder M。

---

## 1. 文件体系总览

| 文件 | 用途 | 格式 | 导入方式 |
|------|------|------|----------|
| Par.xlsx | 参数表（输入/输出/InOut参数声明） | Excel | Control Builder 导入 |
| Var.xlsx | 变量表（内部变量声明） | Excel | Control Builder 导入 |
| Fun.xlsx | 功能块实例表（TOf/AlarmCond等实例） | Excel | Control Builder 导入 |
| Ext.xlsx | 扩展表（通常为空） | Excel | Control Builder 导入 |
| xxx_DataType.xlsx | 自定义结构体数据类型定义 | Excel | Data Type Editor 导入 |
| xxx_Code.st | 纯代码体（粘贴到Code编辑器） | 文本 | 手动复制粘贴 |

**关键原则：表格负责声明，Code 只负责执行逻辑。**

---

## 2. 各表格规则

### 2.1 Par 表（参数表）

- 定义功能块的外部接口：`in`（输入）、`out`（输出）、`in_out`（输入输出）
- 数据类型必须与实际用途匹配
- 硬件 I/O 映射的字段，数据类型必须带 `IO` 后缀（见第4节）
- 功能块内部输出变量（非直接硬件映射）用普通类型 `DInt`、`bool` 等
- `Direction` 列：`in` / `out` / `in_out`
- `FD Port` 列：需要连接图形端口的填 `yes`

### 2.2 Var 表（变量表）

**只声明简单变量，不声明功能块实例。**

- 临时中间变量（如 DInt 转换变量）在此声明
- 字符串常量、时间变量、状态缓存 bool 在此声明
- 功能块实例（TOf、AlarmCond、SimpleEventDetector）**不在此声明**，在 Fun 表中声明
- `Initial Value` 列可以填 `T#1S`、`FALSE`、`'string'` 等初始值
- `Start Attribute` 列可填 `retain`（掉电保持）

### 2.3 Fun 表（功能块实例表）

- 声明所有需要调用的系统功能块实例
- 列：`Name`（实例名）、`Function Block Type`（类型）、`Description`
- 常用类型：`TOf`（断电延时）、`AlarmCond`（报警条件）、`SimpleEventDetector`（事件检测）
- 实例名必须与 Code 中的调用名一致

### 2.4 Ext 表（扩展表）

- 通常为空，只有标题行和表头
- 不要在 Ext 表中放 STRUCT 定义或任何数据

### 2.5 DataType 表（自定义数据类型）

- 在 Control Builder 的 **Data Type Editor** 中通过导入表格创建
- 用于定义 Profibus DP 通讯的结构体（如 `KDMC2880_OUT`、`KDMC2880_IN`）
- **不能使用 ST 语言定义**，只能通过表格导入
- 参考格式：`VVVFDT_DataType.xlsx`

## 3. 代码体（Code.st）规则

### 3.1 纯代码体

Code 编辑器中**只放可执行代码**，不要包含以下声明：

```
❌ FUNCTION_BLOCK xxx
❌ VAR_INPUT / VAR_OUTPUT / VAR / VAR_IN_OUT
❌ END_FUNCTION_BLOCK
```

这些声明通过 Par/Var/Fun 表导入，Code 编辑器只需要中间的逻辑代码。

### 3.2 时间字面量

`T#1S`、`T#2S` 等时间字面量**不能出现在 Code 中**，只能写在 Var 表的 `Initial Value` 列。

```st
❌ flt_time := T#1S ;           (* 编译报错：Expression expected *)

✅  (* Var 表中声明：flt_time : time, Initial Value = T#1S *)
    (* Code 中直接使用变量名 *)
    TOf_Ready(IN := DCS_Ready, PT := flt_time) ;
```

### 3.3 功能块参数名

必须使用正确的参数名，否则报 `Undefined function block parameter`。

| 功能块类型 | 正确参数 | 错误参数 |
|-----------|---------|---------|
| AlarmCond | `Signal` | ~~Condition~~ |
| AlarmCond | `Message` | ~~AlarmText~~ |
| AlarmCond | `Severity` | - |
| AlarmCond | `SrcName` | - |
| AlarmCond | `EnDetection` | - |
| SimpleEventDetector | `Signal` | ~~Condition~~ |
| SimpleEventDetector | `Message` | ~~EventText~~ |
| TOf | `IN` | - |
| TOf | `PT` | - |
| TOf | `Q`（输出） | - |

调用示例：

```st
AlarmCond_Fault(
    Signal := DCS_GenFault ,
    Message := fault_msg ,
    Severity := 800 ,
    SrcName := src_name ,
    EnDetection := TRUE
) ;

EventDet_Start(
    Signal := DCS_Running AND NOT prev_running ,
    Message := start_msg
) ;
```

### 3.4 未使用的功能块实例

Fun 表中声明的实例**必须在 Code 中被调用**，否则产生警告 `Function block not called`。

如果声明了滤波实例但暂时不需要，仍需在 Code 中调用（可以用条件跳过逻辑）。

## 4. GSD 数据类型与硬件 I/O 类型

### 4.1 GSD 导入的数据类型选择

GSD 文件导入时，ABB 800XA 提供以下转换选项：

| GSD 原始类型 | 可选转换 | 用途 |
|-------------|---------|------|
| UInt 16 | **DwordIO** | 位打包字段（状态位、命令位） |
| Signed Int 16 | **DintIO** | 数值字段（温度、压力、设定值） |

### 4.2 DataType 表必须使用 IO 类型

硬件配置中实际使用的数据类型带 `IO` 后缀：

| 用途 | 正确类型 | 错误类型 |
|------|---------|---------|
| 位打包字段（DP通讯字） | `DwordIO` | ~~DWord~~ |
| 数值字段（DP通讯字） | `DintIO` | ~~DInt~~ |

**DataType 表中所有字段必须使用 `DwordIO` / `DintIO`**，否则与硬件 I/O 映射不兼容。

### 4.3 内部变量使用普通类型

Var 表中的中间变量不是硬件 I/O，使用普通类型：

| 用途 | 类型 |
|------|------|
| DWord 转换后的中间变量 | `DInt` |
| 功能块输出参数 | `DInt`、`bool` 等 |

## 5. DWord 位操作规则（核心难点）

### 5.1 问题

ABB 800XA ST 语言**不支持** DWord 类型与 `16#` 十六进制字面量之间直接做 `AND` / `OR` 操作：

```st
❌ DCS_Ready := (wInStatus AND 16#0001) <> 0 ;   (* 编译报错 *)
❌ wOutCtrl := wOutCtrl OR 16#0001 ;               (* 编译报错 *)
```

### 5.2 DwordIO / DintIO 必须使用 .Value 属性

`DwordIO` / `DintIO` 是硬件 I/O 类型，与普通的 `DWord` / `DInt` **不能直接赋值或转换**。必须通过 `.Value` 属性访问底层数值：

```st
❌ in_status := DWORD_TO_DINT(DP_IN.wStatus) ;        (* Type mismatch! DP_IN.wStatus 是 DwordIO *)
❌ DP_OUT.wCtrl := DINT_TO_DWORD(out_int) ;            (* Type mismatch! DP_OUT.wCtrl 是 DwordIO *)
❌ DCS_ChamberNo := DP_IN.iChamberNo ;                 (* Type mismatch! DintIO ≠ DInt *)

✅ in_status := DWORD_TO_DINT(DP_IN.wStatus.Value) ;   (* .Value 取出 DWord *)
✅ DP_OUT.wCtrl.Value := DINT_TO_DWORD(out_int) ;      (* .Value 写入 DWord *)
✅ DCS_ChamberNo := DP_IN.iChamberNo.Value ;           (* .Value 取出 DInt *)
```

### 5.3 解决方案：DInt 中间变量 + MOD/DIV

参考 `SMOTOR_PROV_Code.st` 的模式，通过 `.Value` 取出 DWord，再用 `DWORD_TO_DINT()` 转换为 DInt，最后用除法和取模提取位。

**解包（DwordIO → bool）：**

```st
(* Step 1: DwordIO.Value → DWord → DInt 转换 *)
in_status := DWORD_TO_DINT(DP_IN.wStatus.Value) ;

(* Step 2: 用 (value / bit_position) MOD 2 = 1 提取每个位 *)
DCS_Ready   := (in_status MOD 2) = 1 ;           (* Bit 0  *)
DCS_RunNet  := ((in_status / 2) MOD 2) = 1 ;     (* Bit 1  *)
DCS_RunHard := ((in_status / 4) MOD 2) = 1 ;     (* Bit 2  *)
DCS_Running := ((in_status / 32) MOD 2) = 1 ;    (* Bit 5  *)
```

位位置对照表：

| Bit | 除数 | Bit | 除数 | Bit | 除数 |
|-----|------|-----|------|-----|------|
| 0 | 1 | 5 | 32 | 10 | 1024 |
| 1 | 2 | 6 | 64 | 11 | 2048 |
| 2 | 4 | 7 | 128 | 12 | 4096 |
| 3 | 8 | 8 | 256 | 13 | 8192 |
| 4 | 16 | 9 | 512 | 14 | 16384 |

**打包（bool → DWord）：**

```st
(* Step 1: 用 DInt 加法累加各位 *)
out_int := 0 ;
IF DCS_Start THEN
    out_int := out_int + 1 ;      (* Bit 0  *)
END_IF ;
IF DCS_FeedMode THEN
    out_int := out_int + 2 ;      (* Bit 1  *)
END_IF ;

(* Step 2: DInt → DWord → DwordIO.Value 写入 *)
DP_OUT.wCtrl.Value := DINT_TO_DWORD(out_int) ;
```

### 5.4 转换函数

| 方向 | 函数 |
|------|------|
| DWord → DInt | `DWORD_TO_DINT()` |
| DInt → DWord | `DINT_TO_DWORD()` |

## 6. 开发流程清单

### 6.1 准备阶段

- [ ] 阅读 GSD 文件，确认 DP 从站模块配置（字数、地址）
- [ ] 阅读设备通讯数据表，确认每个字的含义（位定义 / 数值范围）
- [ ] 参考已有功能块（如 SMOTOR_PROV）的表格格式

### 6.2 创建数据类型

- [ ] 确定 DP 输出结构体字段（位打包用 DwordIO，数值用 DintIO）
- [ ] 确定 DP 输入结构体字段
- [ ] 创建 DataType xlsx 表
- [ ] 在 Control Builder Data Type Editor 中导入

### 6.3 创建表格

- [ ] Par 表：参数声明（方向、类型、FD Port）
- [ ] Var 表：内部变量（DInt 中间变量、字符串、时间、bool 缓存）
- [ ] Fun 表：功能块实例（TOf、AlarmCond、SimpleEventDetector）
- [ ] Ext 表：空（只有标题和表头）

### 6.4 编写代码

- [ ] 纯代码体，不含任何 VAR 声明
- [ ] 不使用 `T#` 时间字面量
- [ ] DwordIO / DintIO 字段访问必须加 `.Value`
- [ ] 使用 `DWORD_TO_DINT()` + MOD/DIV 进行位操作
- [ ] 使用 `DINT_TO_DWORD()` 进行打包
- [ ] AlarmCond 参数：Signal / Message / Severity / SrcName / EnDetection
- [ ] SimpleEventDetector 参数：Signal / Message
- [ ] Fun 表中所有实例都在 Code 中被调用

### 6.5 导入与编译

1. 先在 Data Type Editor 中创建结构体类型
2. 导入 Par 表 → Var 表 → Fun 表 → Ext 表
3. 粘贴 Code 代码体
4. 编译检查

## 7. 常见错误速查表

| 错误信息 | 原因 | 解决方法 |
|---------|------|---------|
| `Identifier too long or invalid` (Ext表) | Ext 表中放了 STRUCT 定义 | 清空 Ext 表数据行 |
| `not unique` / `Data type not found` (Var表) | Var 表中声明了 FB 实例 | FB 实例移到 Fun 表 |
| `Data type xxx not found` (Par表) | 自定义类型未创建 | 先在 Data Type Editor 创建结构体 |
| `Identifier, constant or opening parenthesis expected` (Code) | Code 中包含 VAR 声明 | 删除所有声明，只保留执行代码 |
| `Expression expected` (Code, T#) | Code 中使用了 T# 时间字面量 | 时间值移到 Var 表 Initial Value |
| `Undefined function block parameter` (Code) | AlarmCond/SimpleEventDetector 参数名错误 | 改为 Signal / Message / Severity 等 |
| `Function block not called` (Warning) | Fun 表中声明的实例未在 Code 调用 | 在 Code 中添加调用代码 |
| `Identifier, constant or opening parenthesis expected : Row N` (Code) | DWord 与 16# 做 AND/OR | 改用 DInt + MOD/DIV 方式 |
| 硬件 I/O 类型不匹配 | DataType 表用了 DWord/DInt | 改为 DwordIO / DintIO |
| `Type mismatch` (Code, DwordIO/DintIO) | DwordIO/DintIO 字段直接赋值或转换 | 加 `.Value` 属性访问底层数值 |
