> 适用于 ABB 800XA V6.1.0 Control Builder M
> 汇总自 SIMOCODE S3UF7E、ABB_LV/MV_VVVF、KDMC2880 除尘器、INTECONT Tersus 皮带秤等功能块开发经验
> 最后更新：2026-07-15

## 一、最高优先级规则：.Value 属性访问 I/O 类型

### 1.1 根本原则

**所有硬件 I/O 类型（DintIO、RealIO、DwordIO）在 ST 代码中必须通过 `.Value` 属性访问底层标准类型，不能直接赋值或参与运算！**

违反此规则会报 Error 1030 (Type mismatch)。

```
DintIO.Value   → DInt    读: x := dpIn_Status.Value;      写: dpOut_Ctrl.Value := x;
RealIO.Value   → Real    读: x := dpIn_Flow.Value;        写: dpOut_FlowSet.Value := x;
DwordIO.Value  → DWord   读: x := DP_IN.wStatus.Value;    写: DP_OUT.wCtrl.Value := DINT_TO_DWORD(x);
```

### 1.2 GSD 模块位宽与类型对照

| GSD 模块位宽 | 硬件通道类型 | .Value 返回 | ST 中是否需转换 |
|---|---|---|---|
| 16-bit | DwordIO | DWord | 需要 DWORD_TO_DINT / DINT_TO_DWORD |
| 32-bit 整数 | DintIO | DInt | **不需要转换，直接使用** |
| 32-bit 浮点 | RealIO | Real | **不需要转换，直接使用** |

### 1.3 错误示例与正确写法

```st
(* 错误：直接访问 I/O 类型 *)
in_status1_int := dpIn_Status1 ;            ← Error 1030!
Actual_Flow := dpIn_Flow ;                  ← Error 1030!
dpOut_Ctrl1 := out_ctrl1_int ;              ← Error 1030!
dpOut_Spare0 := 0 ;                         ← Error 1030!

(* 正确：通过 .Value 属性 *)
in_status1_int := dpIn_Status1.Value ;      ← DintIO.Value → DInt
Actual_Flow := dpIn_Flow.Value ;            ← RealIO.Value → Real
dpOut_Ctrl1.Value := out_ctrl1_int ;         ← DInt → DintIO.Value
dpOut_Spare0.Value := 0 ;                   ← 0 → DintIO.Value
```

### 1.4 大布袋代码参考

大布袋代码中已经在使用 `.Value` 属性：

```st
(* 大布袋：DwordIO.Value → DWord，需要转换 *)
DP_OUT.wCtrl.Value := DINT_TO_DWORD(out_int) ;          ← 写
in_status := DWORD_TO_DINT(DP_IN.wStatus.Value) ;        ← 读
DCS_ChamberNo := DP_IN.iChamberNo.Value ;                 ← 读
```

### 1.5 32-bit 比 16-bit 更简单

- 16-bit（大布袋）：`.Value` 返回 DWord，需要 `DWORD_TO_DINT` / `DINT_TO_DWORD` 转换
- 32-bit（皮带秤）：`.Value` 返回 DInt 或 Real，直接使用，无需任何转换函数

**Error 1030 是最常见的错误，99% 的情况是因为 I/O 类型缺少 `.Value` 属性。**

## 二、文件体系

### 2.1 文件组成

每个功能块需要以下文件，**表格负责声明，Code 只负责执行逻辑**：

| 文件 | 用途 | 格式 | 导入方式 |
|------|------|------|----------|
| `FBName_Par.xlsx` | 参数表（输入/输出/InOut 外部接口） | Excel | Control Builder 导入 |
| `FBName_Var.xlsx` | 变量表（内部中间变量） | Excel | Control Builder 导入 |
| `FBName_Fun.xlsx` | 功能块实例表（TOf/AlarmCond 等实例） | Excel | Control Builder 导入 |
| `FBName_Ext.xlsx` | 扩展表（通常为空） | Excel | Control Builder 导入 |
| `FBName_Code.st` | ST 纯代码体（可执行部分） | 文本 | 手动复制粘贴 |
| `xxx_DataType.xlsx` | 自定义结构体数据类型（STRUCT 路线用） | Excel | Data Type Editor 导入 |

### 2.2 STRUCT 路线 vs 独立变量路线

STRUCT 和独立变量路线都可以用于 16-bit 和 32-bit 设备，区别在于 `.Value` 的使用方式：

| 路线 | 适用场景 | DP 参数数量 | ST 中访问方式 | 文件数 |
|---|---|---|---|---|
| STRUCT | 需要减少参数数量时 | 2 个 (DP_IN, DP_OUT) | `DP_IN.dwStatus.Value` | 6 个（含 DataType） |
| 独立变量 | 需要直接映射硬件通道时 | 每个 DP 字一个参数 | `dpIn_Status.Value` | 5 个（无 DataType） |

### 2.3 16-bit vs 32-bit 完整对比

| 对比项 | 16-bit（大布袋） | 32-bit（皮带秤） |
|---|---|---|
| 路线 | STRUCT | 独立变量 |
| 文件数量 | 6 个（含 DataType） | 5 个（无 DataType） |
| DP 参数 | 2 个 (DP_IN, DP_OUT) | 16 个独立参数 |
| 硬件通道类型 | DwordIO | DintIO / RealIO |
| .Value 返回 | DWord | DInt / Real |
| ST 转换函数 | 需要 DWORD_TO_DINT | 不需要，直接使用 |
| 字段访问示例 | `DP_IN.wStatus.Value` | `dpIn_Status1.Value` |

### 2.4 文件命名规范

| 文件 | 命名规则 | 示例 |
|------|---------|------|
| 参数表 | `设备型号_Par.xlsx` | `KDMC2880_Par.xlsx` |
| 变量表 | `设备型号_Var.xlsx` | `KDMC2880_Var.xlsx` |
| 功能块表 | `设备型号_Fun.xlsx` | `KDMC2880_Fun.xlsx` |
| 扩展表 | `设备型号_Ext.xlsx` | `KDMC2880_Ext.xlsx` |
| 输出数据类型 | `设备型号_OUT_DataType.xlsx` | `KDMC2880_OUT_DataType.xlsx` |
| 输入数据类型 | `设备型号_IN_DataType.xlsx` | `KDMC2880_IN_DataType.xlsx` |
| 纯代码体 | `设备型号_Code.st` | `KDMC2880_DustCollector_Code.st` |

### 2.5 Excel 通用格式

**标题行：**
- 必须包含库前缀：`Function Block Type - TAYNINH.FBName`
- ST 代码中**不加前缀**：`FUNCTION_BLOCK FBName`（带点号报 Error 1116）

**标准格式（与老功能块一致）：**
- 第1行：合并标题行
- 第2行：列头
- 数据行：序号 + 内容
- 最后行：日期 + 页码（如 `2026-07-14 20:09  - 1 -`）

### 2.6 导入顺序

1. （STRUCT 路线）在 Data Type Editor 中创建结构体类型
2. 导入 Var 表
3. 导入 Par 表
4. 导入 Fun 表
5. 粘贴 ST 代码
6. 编译

## 三、各表格详细规则

### 3.1 Par 表（参数表）

定义功能块的**外部接口**。

| 列 | 说明 | 取值 |
|----|------|------|
| Direction | 参数方向 | `in` 只读输入 / `out` 只写输出 / `in_out` 读写 |
| FD Port | 图形端口连接 | 需要连接填 `yes` |
| Start Attribute | 保持属性 | `retain` / `coldretain` / 空 |
| Data Type | 数据类型 | 硬件 I/O 映射必须带 `IO` 后缀 |

**关键规则：**
- `in_out` 方向**不能**带 `retain` 属性（Error 1005）
- `in` 方向参数是只读的，代码中赋值报 Error 1034
- 既要读又要写的参数，放在 PAR 中设 `in_out`，不要在 VAR 中重复声明
- 独立变量路线：DP 字用独立 DintIO/RealIO 参数，方向 in_out
- STRUCT 路线：DP_IN/DP_OUT 用自定义 STRUCT 类型，方向 in_out

### 3.2 Var 表（变量表）

**只声明简单变量，不声明功能块实例。**

- 临时中间变量（DInt 转换变量、bool 缓存）在此声明
- 字符串常量、时间变量在此声明
- 功能块实例（TOf、AlarmCond 等）**不在此声明**，移到 Fun 表
- Initial Value 列可填 `T#1S`、`FALSE`、`'string'` 等
- Start Attribute 可填 `retain`（掉电保持）

### 3.3 Fun 表（功能块实例表）

声明所有 ST 代码中调用的功能块实例。

| 列 | 说明 |
|----|------|
| Name | 实例名（必须与 Code 中调用名一致） |
| Function Block Type | FB 类型名（**大小写敏感**） |
| Task Connection | 任务连接（通常为空） |
| Description | 描述 |

**类型名大小写严格正确：**

| 正确 | 错误 | 说明 |
|------|------|------|
| `TOf` | `TOF` | 断电延时定时器 |
| `TOn` | `TON` | 通电延时定时器 |
| `TP` | - | 脉冲定时器 |
| `RS` | - | 复位优先锁存器 |
| `SR` | - | 置位优先锁存器 |
| `R_Trig` | - | 上升沿触发 |
| `F_Trig` | - | 下降沿触发 |
| `CTU` | - | 加计数器 |
| `AlarmCond` | - | 报警条件 |
| `SimpleEventDetector` | - | 事件检测 |
| `TimerU` | - | 运行时间计时器 |
| `Dint_bool16` | - | TAYNINH 库自定义 |
| `BOOL16_DINT` | - | TAYNINH 库自定义 |

**调用规则：**
- Fun 表中所有实例必须在 Code 中被调用（Warning 1542）
- 即使只引用 `.Q` 输出，也必须显式调用功能块实例
- ST 代码方式必须手动声明，FBD 图形方式会自动处理

### 3.4 Ext / COD 表（扩展表）

- 通常为空，只有标题行和表头
- **不要**放 STRUCT 定义或任何数据（报 `Identifier too long or invalid`）

### 3.5 DataType 表（自定义数据类型，STRUCT 路线用）

- 在 **Data Type Editor** 中通过表格导入创建
- 用于定义 Profibus DP 通讯结构体（如 `KDMC2880_OUT`、`ITEC_BOUT`）
- **不能用 ST 语言定义**，只能通过表格导入
- 硬件 I/O 字段必须使用带 `IO` 后缀的类型（DwordIO/DintIO/RealIO）
- ST 代码中通过 `.Value` 属性访问字段

## 四、ST 代码语法规则

### 4.1 Code 只放可执行代码

Code 编辑器中**只放逻辑代码**，不要包含声明：

```
❌ FUNCTION_BLOCK xxx
❌ VAR_INPUT / VAR_OUTPUT / VAR / VAR_IN_OUT
❌ END_FUNCTION_BLOCK
```

变量声明通过 Par/Var/Fun 表导入，Code 只写中间执行逻辑。
包含声明会报 Error 1116 `Identifier expected`。

### 4.2 运算符禁止项

| 禁止写法 | 替代方案 | 错误码 |
|---------|---------|--------|
| `DINT AND 16#0001` | `(DINT / 1) MOD 2 = 1` | 1055 |
| `DWORD AND 16#FFFF0000` | 除法右移 | 1055 |
| `STATUS OR 16#0001` | `STATUS + 1` | 1055 |
| `SHR(val, 16)` | `val / 65536` | 1108/1055 |
| `WORD#0` / `DWORD#0` | 直接写 `0` | 1104 |

### 4.3 字符串限制

- **ST 代码中不允许任何字符串字面量**（单引号、双引号都不行）
- 报 Error 1104 / 1116
- 替代：在 Var 表定义字符串变量，Initial Value 写 `'xxx'`，代码中引用变量名

### 4.4 时间常量限制

- **Code 中禁止** `T#100D`、`T#0S`、`T#1S` 等时间字面量
- 报 Error `Expression expected`
- 替代：Var 表中定义 TIME 类型变量，Initial Value 写 `T#1S`，代码中引用变量名

### 4.5 功能块调用格式

**简单 FB（RS/TP/TOn 等）必须单行：**
```st
(* 正确 *)
RS_Drive(Set := start AND lock, R1 := stop OR fault);

(* 错误：报 Error 1024 *)
RS_Drive(
    Set := start AND lock,
    R1 := stop OR fault
);
```

**多参数 FB（Dint_bool16 等）换行规则：**
- 参数间用逗号分隔
- **最后一个参数后无逗号**（禁止尾随逗号，Error 1104/1116）
- `);` 紧跟最后一个参数，**不能单独一行**（Error 1023）

## 五、标准功能块引脚名

### 5.1 引脚速查表

| FB 类型 | 置位引脚 | 复位引脚 | 输出 | 输入引脚 |
|---------|----------|---------|------|---------|
| **RS** | `Set` | `R1` | `Q1` | — |
| **SR** | `S1` | `Reset` | `Q1` | — |
| **TOn** | — | — | `Q` | `In`, `PT` |
| **TOf** | — | — | `Q` | `In`, `PT` |
| **TP** | — | — | `Q` | `In`, `PT` |
| **F_Trig** | — | — | `Q` | `Clk` |
| **R_Trig** | — | — | `Q` | `Clk` |

### 5.2 易错参数名

| 错误写法 | 正确写法 | 说明 |
|---------|---------|------|
| `RS(Reset1 := ...)` | `RS(R1 := ...)` | RS 复位是 `R1` 不是 `Reset1` |
| `SR(R1 := ...)` | `SR(Reset := ...)` | SR 复位是 `Reset` 不是 `R1` |
| `TOn(IN := ...)` | `TOn(In := ...)` | 定时器输入是 `In`（首字母大写） |
| `F_Trig(IN := ...)` | `F_Trig(Clk := ...)` | 触发器输入是 `Clk` |

### 5.3 引脚名大小写敏感

变量名大小写不敏感，但 **FB 引脚名大小写敏感**：
- `In` 正确，`IN` 错误
- `Set` 正确，`SET` 错误
- `Clk` 正确，`CLK` 错误

### 5.4 其他功能块参数

| 功能块 | 参数名 | 注意 |
|--------|--------|------|
| CTU | `CU`, `RESET`, `PV` | - |
| AlarmCond | `Signal`, `Message`, `Severity`, `SrcName`, `EnDetection` | **不支持 CondName** |
| SimpleEventDetector | `Signal`, `Message` | - |
| TimerU | `Hold`, `Reset`, `PT`, `ST`, `PTChRst` | - |

## 六、功能块使用规范

### 6.1 TOf（Off-Delay Timer）

**用途：** 信号滤波，防止噪声引起的瞬间抖动

```st
TOf_Run(IN := Running, PT := t1s) ;
Running := TOf_Run.Q ;  (* 信号消失后延时 1s 才变为 FALSE *)
```

**适用场景：** Running、Heavy_Alarm、Warning 等关键状态信号

### 6.2 TP（Pulse Timer）

**用途：** 生成固定宽度脉冲，用于 Start/Stop/Reset 命令

```st
TP_Start(IN := DCS_Start, PT := t1s) ;  (* 产生 1s 脉冲 *)
```

**适用场景：** 仅 Start/Stop/Reset 用 TP；其他命令（去皮、标定等）直接打包，不需要 TP

### 6.3 AlarmCond（报警条件）

```st
AlarmCond_1(
    Signal := Heavy_Alarm ,
    Message := msg_alarm ,
    Severity := 800 ,        (* 800=重报警, 500=警告 *)
    SrcName := ASrcname ,
    EnDetection := TRUE
) ;
```

### 6.4 SimpleEventDetector（事件检测）

**内部自动检测上升沿，但停止事件需要手动反逻辑：**

```st
(* 启动事件：Running 上升沿 *)
SimpleEventDetector_1(
    Signal := Running AND NOT prev_running ,
    Message := msg_start
) ;

(* 停止事件：Running 下降沿 = NOT Running 上升沿 *)
SimpleEventDetector_2(
    Signal := (NOT Running) AND prev_running ,
    Message := msg_stop
) ;
```

**关键：** prev_running 必须在 Var 表中声明，并在代码末尾更新：

```st
prev_running := Running ;
```

## 七、自定义功能块（TAYNINH 库）

### 7.1 与标准类型的区别

TAYNINH 库的自定义 FB 与标准 `DINTTOBOOL16`/`BOOL16TODINT` 完全不同：

| 特性 | 标准 DINTTOBOOL16 | TAYNINH Dint_bool16 |
|------|-------------------|---------------------|
| 输入 | `Int` (DINT) | `in` (DINT) |
| 输出 | `BoolStruct` (Boolean16) + `Status` | `bool0`~`bool15`（16个独立 bool） |

| 特性 | 标准 BOOL16TODINT | TAYNINH BOOL16_DINT |
|------|-------------------|---------------------|
| 输入 | `BoolStruct` (Boolean16) | `IN0`~`IN15`（16个独立 bool） |
| 输出 | `Int` (DINT) + `Status` | `OUT` (DINT) |

### 7.2 调用示例

```st
(* DINT → 16个独立bool *)
Dint_bool16_1(
    in := VVVFDINT.INPUTDINT1.Value,
    bool0 => INBOOL1_B0,
    bool1 => INBOOL1_B1,
    ...
    bool15 => INBOOL1_B15);

(* 16个独立bool → DINT *)
BOOL16_DINT_1(
    IN0 := OUTBOOL1_B0,
    IN1 := OUTBOOL1_B1,
    ...
    IN15 := OUTBOOL1_B15,
    OUT => VVVFDINT.OUTPUTDINT1.Value);
```

### 7.3 32 位版本

还有 `Dint_bool32` / `BOOL32_DINT`，引脚结构类似（`bool0`~`bool31` / `IN0`~`IN31`）。

## 八、类型转换与位操作

### 8.1 类型转换函数链

| 转换方向 | 正确写法 | 备注 |
|---------|---------|------|
| DWORD → DINT | `DWORD_TO_DINT(val)` | 16-bit 设备需要 |
| DINT → DWORD | `DINT_TO_DWORD(val)` | 16-bit 设备需要 |
| DWORD → WORD | `DWORD_TO_WORD(val)` | - |
| DINT → REAL | `DINT_TO_REAL(val)` | - |
| WORD → UINT | `WORD_TO_UINT(val)` | - |
| DWORD 右移16位 | `DWORD_TO_DINT(val) / 65536` | 替代 SHR |

### 8.2 不存在的转换函数

| 禁止 | 原因 | 替代方案 |
|------|------|---------|
| `WORD_TO_REAL()` | 未定义（Error 1023） | `DINT_TO_REAL(WORD_TO_UINT(val))` |
| `DINT_TO_BOOL16()` | 未定义（Error 1023） | 位操作 DIV/MOD 或 TAYNINH 库 |
| `BOOL16_TO_DINT()` | 未定义（Error 1023） | IF/THEN 累加或 TAYNINH 库 |
| `SHR()` 函数 | 类型不兼容（Error 1055） | 除法 `/ 65536` |

### 8.3 位解包（DWord/DInt → bool）

**16-bit 设备（DwordIO → DWord → DInt → MOD/DIV）：**

```st
in_status := DWORD_TO_DINT(DP_IN.wStatus.Value) ;
DCS_Ready   := (in_status MOD 2) = 1 ;          (* Bit 0 *)
DCS_RunNet  := ((in_status / 2) MOD 2) = 1 ;    (* Bit 1 *)
DCS_Running := ((in_status / 32) MOD 2) = 1 ;   (* Bit 5 *)
```

**32-bit 设备（DintIO → DInt 直接，无需转换）：**

```st
in_status1_int := dpIn_Status1.Value ;
Running    := (in_status1_int MOD 2) = 1 ;          (* Bit 0 *)
No_Release := ((in_status1_int / 2) MOD 2) = 1 ;    (* Bit 1 *)
```

**位值速查表：**

| Bit | 值 | 表达式 | Bit | 值 | 表达式 |
|---|---|---|---|---|---|
| 0 | 1 | MOD 2 | 8 | 256 | /256 MOD 2 |
| 1 | 2 | /2 MOD 2 | 9 | 512 | /512 MOD 2 |
| 2 | 4 | /4 MOD 2 | 10 | 1024 | /1024 MOD 2 |
| 3 | 8 | /8 MOD 2 | 11 | 2048 | /2048 MOD 2 |
| 4 | 16 | /16 MOD 2 | 12 | 4096 | /4096 MOD 2 |
| 5 | 32 | /32 MOD 2 | 13 | 8192 | /8192 MOD 2 |
| 6 | 64 | /64 MOD 2 | 14 | 16384 | /16384 MOD 2 |
| 7 | 128 | /128 MOD 2 | 16 | 65536 | /65536 MOD 2 |
| 30 | 1073741824 | /1073741824 MOD 2 | | | |

### 8.4 位打包（bool → DWord/DInt）

**16-bit 设备（IF 累加 → DInt → DWord → DwordIO.Value）：**

```st
out_int := 0 ;
IF DCS_Start THEN out_int := out_int + 1 ; END_IF ;   (* Bit 0 *)
IF DCS_FeedMode THEN out_int := out_int + 2 ; END_IF ; (* Bit 1 *)
DP_OUT.wCtrl.Value := DINT_TO_DWORD(out_int) ;
```

**32-bit 设备（IF 累加 → DInt → DintIO.Value，无需转换）：**

```st
out_ctrl1_int := 0 ;
IF TP_Start.Q THEN
    out_ctrl1_int := out_ctrl1_int + 1 ;      (* Bit 0 *)
END_IF ;
out_ctrl1_int := out_ctrl1_int + 8 ;          (* Bit 3: 释放位，始终为 1 *)
dpOut_Ctrl1.Value := out_ctrl1_int ;
```

**Bit 31 打包技巧：** DInt 最大值为 2^31-1 = 2147483647，不能直接加 2^31。使用 `- 2147483647 - 1` 等价于设置 Bit 31 为 1。

### 8.5 浮点值传输

```st
(* 32-bit 设备：RealIO.Value → Real，无需转换 *)
Actual_Flow := dpIn_Flow.Value ;
dpOut_FlowSet.Value := Flow_Setpoint ;
```

## 九、DP 通信地址表解读

### 9.1 WORD 编号规则

**PROFIBUS 通信地址表使用 2 字节 WORD 编号，不是字节偏移！**

```
"控制字 04+05" = 2-byte Word 编号 4 和 5
            = bytes 8-11（第 3 个 4 字节）
            = 从字节 0 开始数：0-3(Word0-1), 4-7(Word2-3), 8-11(Word4-5)
```

## 十、变量命名规则

### 10.1 大小写不敏感

800XA 编译器对变量名**大小写不敏感**（Error 1000）：
- `Local_permission` = `LOCAL_PERMISSION` = `local_permission`

同一功能块内不能仅靠大小写区分名称，必须改变拼写（如 `LOCAL_PERM`）。

### 10.2 VAR + PAR 全局唯一

变量名在 **VAR 表和 PAR 表合并后**必须唯一，不能两张表同名。
- 反面案例：`SET_AUTO` 同时出现在 VAR 和 PAR → Error 1000
- 规则：一个变量只在一处声明；既要读又要写的参数放 PAR 设 `in_out`

### 10.3 方向与属性约束

| 场景 | 规则 | 错误码 |
|------|------|--------|
| `in_out` + `retain` | 不允许同时使用 | 1005 |
| `in` 方向在代码中赋值 | 不允许，只读 | 1034 |

### 10.4 常见变量命名对照

| 避免使用 | 推荐替代 | 说明 |
|---------|---------|------|
| `stop` | `Single_stop` | 通用停止条件 |
| `T_RST` | `Reset` | 复位信号 |
| `t1s` | `pt_time` | 1秒延时 |
| `safetylock_time` | `safe_lock_time` | 安全锁延时 |
| `safetylock_msg` | `safe_lock_msg` | 安全锁消息 |

### 12.1 通信模块对比

| 信号 | 换算关系 | 说明 |
|------|---------|------|

| 功率 ACT | 10 = 1kW | 驱动参数映射 |
| 温度 ACT | 10 = 1°C | MV 专用 |

### 12.4 控制字（CW）关键位

| Bit | 名称 | 说明 |
|-----|------|------|
| 0 | OFF1 | 1=运行，0=斜坡停车 |
| 1 | OFF2 | 1=运行，0=自由停车 |
| 2 | OFF3 | 1=运行，0=快速急停 |
| 3 | OPERATION_ENABLE | 1=允许运行 |
| 7 | RESET | 0→1 故障复位 |
| 10 | REMOTE_CMD | 1=总线控制使能 |

### 12.5 状态字（SW）关键位

| Bit | 名称 | 说明 |
|-----|------|------|
| 0 | RDY_ON | 1=准备合闸 |
| 1 | RDY_RUN | 1=准备操作 |

| 7 | ALARM | 1=警告 |
| 8 | AT_SETPOINT | 1=运行中（达到给定） |

### 12.6 CW 常用十六进制值

## 十三、设备特有规则

### 13.1 皮带秤（INTECONT Tersus）
- 设备：Schenck INTECONT Tersus，Ident: 0x0C9B
- GSD 模块：FIXED_8_8（32 bytes IN + 32 bytes OUT）
- 32-bit 模块 → 独立变量路线，Par 表用 DintIO/RealIO
- 配料秤和皮带秤共用一个功能块，皮带秤不接 Flow_Setpoint 即可
- 流量设定值位置：bytes 16-19（words 8-9，QW.12，RealIO）
- DP 参数命名：dpOut_* / dpIn_* 前缀区分方向
- Release bit（控制字1 Bit 3）必须始终为 1
- Bit 31 打包用 `- 2147483647 - 1` 避免 DInt 溢出

### 13.2 大布袋（KDMC2880）
- 16-bit GSD 模块 → DwordIO → STRUCT 路线
- STRUCT 字段用 DwordIO，ST 中 `.Value` 返回 DWord，需要 DWORD_TO_DINT / DINT_TO_DWORD 转换
- 报警用 `AlarmCond`，事件用 `SimpleEventDetector`
- 结构体在 Data Type Editor 中通过表格导入创建

### 13.3 S3UF7E（SIMOCODE 马达保护器）

**数据字映射：**
- `SWORD.Inputdw1.Value`：状态字 + 电流值（高16位）
- `SWORD.Inputdw2.Value`：电流 Ib（低16位）+ 电流 Ic（高16位）
- `SWORD.Inputdw3.Value`：电压 Ua（低16位）
- `SWORD.Outputdw1.Value`：输出控制字（唯一输出）

### 13.4 LV 与 MV 变频器差异

| 特性 | ABB_LV_VVVF（低压） | ABB_MV_VVVF（中压） |
|------|---------------------|---------------------|
| 通信模块 | FPBA-01 | RPBA-01 |
| 行规 | ABB Drives | PROFIdrive |
| 电机温度监控 | 无 | 有（motor_temp, TEMP_ALARM） |
| 控制模式 | 仅频率 | 频率/转速/百分比（set_type） |
| 急停定时器 | 无 | 有（TOf_1, ES_TIME） |
| Dint_bool16 实例数 | 2 | 3 |
| 报警数量 | 4 | 6 |

## 十四、常见错误速查表

| 错误码 | 含义 | 常见原因 | 解决方法 |
|--------|------|----------|---------|
| 1000 | 变量名不唯一 | VAR/PAR 重名；大小写不敏感冲突 | 合并去重 |
| 1001 | Data type not found | STRUCT 未创建 | 创建 STRUCT 或不用 STRUCT |
| 1002 | FB 类型未找到 | 自定义 FB 未导入；类型名拼写错误 | 检查 Fun 表类型名 |
| 1005 | retain 不允许 | in_out 方向带了 retain | 移除 retain |
| 1023 | 未定义 FB 实例 | Fun 表未声明该实例 | 在 Fun 表添加声明 |
| 1024 | 未定义 FB 参数 | 引脚名错误（Reset1 vs R1）或调用跨行 | 修正引脚名，简单FB单行 |
| 1028 | IN/OUT 参数无引用 | Boolean16 转换函数用法错误 | 改用正确绑定方式 |
| 1030 | Type mismatch | **I/O 类型缺少 .Value 属性** | **加 .Value 属性** |
| 1032 | 变量未声明 | 代码用了 Var/Par 中没有的变量 | 添加声明 |
| 1034 | 不允许修改 | in 方向参数在代码中被赋值 | 改 in_out 或移除赋值 |
| 1053 | 仅允许 int/uint/dint/real | 类型不兼容的运算 | 转换为支持的类型 |
| 1055 | 表达式类型不兼容 | AND/OR 位运算或类型不匹配 | 改用 DIV/MOD 位操作 |
| 1104 | 缺少表达式 | 字符串字面量、类型前缀常量、尾随逗号 | 移除，改用变量/纯数字 |
| 1108 | 缺少右括号 | 函数调用括号不匹配或跨行 | 检查括号配对 |
| 1116 | 缺少标识符 | Code 中有 FUNCTION_BLOCK；逗号缺失/多余；ST带点号 | 移除声明，检查标点 |
| 1117 | 意外符号 | 语法不兼容 | 检查语法格式 |
| 1146 | 缺少分号 | 语句格式错误 | 检查分号位置 |
| 1340 | 非法初始值 | String 初始值缺引号 | 加单引号 |
| 1542 | FB 未调用（警告） | Fun 表有多余未使用实例 | 删除或添加调用 |

**其他常见问题：**

| 现象 | 原因 | 解决方法 |
|------|------|---------|
| Ext 表报 Identifier too long | Ext 表放了 STRUCT 定义 | 清空 Ext 表数据行 |
| Var 表报 not unique / 类型未找到 | Var 表声明了 FB 实例 | FB 实例移到 Fun 表 |
| Par 表报 Data type not found | 自定义类型未提前创建 | 先在 Data Type Editor 创建 |
| 硬件 I/O 类型不匹配 | DataType 用了 DWord/DInt | 改为 DwordIO / DintIO |

## 十五、开发流程检查清单

### 阶段 1：准备
- [ ] 阅读 GSD 文件，确认 DP 从站字数、地址、Ident 号
- [ ] 阅读设备通讯表，确认每个字的位定义/数值范围
- [ ] **确认 GSD 模块位宽**（16-bit → DwordIO，32-bit → DintIO/RealIO）
- [ ] 确认通信行规（ABB Drives vs PROFIdrive）和换算系数
- [ ] 确认是否需要多个功能块（如配料秤和皮带秤可否合并）
- [ ] 参考老功能块，确认 FB 引脚名和变量命名规范
- [ ] 确认 TAYNINH 库可用的自定义 FB 类型

### 阶段 2：创建数据类型（STRUCT 路线）
- [ ] 确定输出结构体字段（位打包 DwordIO，数值 DintIO，浮点 RealIO）
- [ ] 确定输入结构体字段
- [ ] 在 Data Type Editor 中导入
- 独立变量路线跳过此步

### 阶段 3：创建表格
- [ ] Par 表：参数方向、类型、FD Port、retain 属性
- [ ] Var 表：中间变量、时间变量、字符串常量
- [ ] Fun 表：所有用到的 FB 实例，类型名大小写正确
- [ ] Ext 表：空，只有标题和表头
- [ ] Excel 标题包含库前缀 `TAYNINH.FBName`
- [ ] Var 表字符串用单引号（英文），Par 表 Group 行 Initial Value 为空

### 阶段 4：编写 ST 代码
- [ ] 纯代码体，无 FUNCTION_BLOCK/VAR/END_FUNCTION_BLOCK
- [ ] **所有 I/O 类型通过 .Value 属性访问**
- [ ] 无 `T#` 时间字面量（放 Var 表 Initial Value）
- [ ] 无 AND/OR 位运算，用 DIV/MOD 和加法替代
- [ ] 无 `SHR()`，用除法替代
- [ ] 无 `WORD#0`/`DWORD#0` 类型前缀
- [ ] 无字符串字面量
- [ ] 简单 FB 调用单行，复杂 FB 无尾随逗号、`);` 同行
- [ ] RS 用 `R1`，AlarmCond 用 `Signal/Message/Severity/SrcName/EnDetection`
- [ ] 无 `WORD_TO_REAL`、无 `CondName`
- [ ] 变量名 VAR+PAR 合并后唯一，注意大小写不敏感
- [ ] `in_out` 不带 retain，`in` 方向不在代码中赋值
- [ ] FB 引脚名大小写正确（`In` 不是 `IN`）
- [ ] Fun 表中所有实例在 Code 中都有调用
- [ ] prev_running 更新在代码末尾

### 阶段 5：导入与编译
- [ ] （STRUCT 路线）先在 Data Type Editor 创建结构体类型
- [ ] 导入 Var 表
- [ ] 导入 Par 表
- [ ] 导入 Fun 表
- [ ] 粘贴 Code 代码体
- [ ] 编译检查，对照错误码排查

## 十六、禁止事项

- **禁止直接访问 I/O 类型（DintIO/RealIO/DwordIO），必须通过 `.Value` 属性**
- **禁止在 ST 代码中对 I/O 类型变量直接赋值或运算**
- **禁止在 ST 代码中使用 AND/OR/SHR 位运算**，用 DIV/MOD 和加法替代
- **禁止在 ST 代码中包含 VAR/END_VAR 声明**
- **禁止在 ST 代码中使用字符串字面量和时间字面量**
- **禁止在 Var 表中声明 FB 实例**（FB 实例放 Fun 表）
- **禁止在 Ext 表中填写内容**
- **禁止 String 初始值用中文或缺少引号**
- **禁止 `in_out` + `retain` 组合**
- **禁止 `in` 方向参数在代码中赋值**
- **禁止变量名 VAR+PAR 重名**（大小写不敏感）
