# MiniLangGraph 工作流引擎方法论

> 证据边界（贯穿全文）：本稿三类内容分开标注——**【设计】**来自 README（产品文档语气）与开发计划 V4（自标"待审计划"），描述同一设计意图；**【现存实现证据】**来自已落盘代码与提交记录，本任务未运行测试；**【推断】**为方法论延展，非项目官方结论。本稿不声称 MiniLangGraph 测试已通过或已投入日常使用。

## 一、定位与边界【设计】

来源：README 第 1–10 行、开发计划第 7–13 行。

- `minigraph` 是**纯 Python 标准库实现的本地工作流引擎**，借鉴 LangGraph 的状态图、条件路由、检查点和中断概念；**不承诺与 LangGraph 的 API 或边缘行为兼容**。
- 运行要求：Python 3.10+，仅标准库，支持 Windows 与 Linux。
- 节点是**同步 Python 函数**；状态通过**字典增量 + 可配置 reducer** 更新。
- 交付形态：引擎包、声明式流程加载、CLI、示例、测试、最小 README。
- **明确不做（范围边界）**：自动重试策略、线程池并行、子图、知识库同步、git 提交/推送。这五项是边界而非缺陷——引擎不内置，需调用方在节点内自写或用外部脚本编排。

## 二、核心概念：状态图【设计】

来源：README 第 93–106 行、开发计划第 29–62 行。

- `StateGraph(reducers=None)`：声明式建图。
- `add_node(name, fn)`：注册节点，`fn` 签名为 `(dict) -> dict`，返回**状态增量字典**（不原地修改输入）。
- `add_edge(source, target)`：固定边，端点可用节点名 / `START` / `END`。
- `add_conditional_edges(source, router, mapping=None)`：条件边；`router(state) -> str | list[str]`；`mapping=None` 时路由返回值即节点名，多目标表示扇出。固定出边与条件出边互斥。
- `compile()`：编译并校验，返回 `CompiledGraph`。
- 哨兵：`START` / `END` 入口/结束，避免与同名节点冲突；`START` 只允许一种入口定义。
- 异常体系：`GraphError` / `CompileError` / `StateContractError` / `CheckpointError` / `NodeError` / `GraphInterrupt`。

## 三、执行模型：超步快照与同步汇聚【设计】

来源：README 第 140–143 行、开发计划第 64–72 行。

- **超步开始固定状态快照**；本轮候选节点按稳定注册顺序执行；每个节点接收隔离的状态副本。
- 节点返回值必须为状态增量字典；**同超步写入在屏障处统一按节点稳定顺序经 reducer 合并**，不能被同批次其他节点提前观察。
- **汇聚**：分支下游跟踪本轮已选前驱到达；汇聚节点在所有相关前驱到达后进入后续超步，同一轮只进入一次；不等长路径自然等待较慢分支。
- **循环与重试**：回边（含自环）作为重入触发；循环按超步重建到达记录，避免前轮到达被误认本轮已到达；**无条件环不会死锁**，`max_steps` 超限写入 `failed` 检查点并抛出可读 `GraphError`。
- 本期节点**同步、顺序执行**；"扇出"表达图语义，**不代表线程并发**。

## 四、状态契约、检查点与失败恢复【设计】

来源：README 第 144–147 行、开发计划第 79–87 行。

- **状态契约**：持久化状态、节点返回增量及 `state_update` 限于 JSON 原生类型（`str/int/float/bool/None/list/dict`，字典键必须为 `str`）；违反时报出节点与字段路径。可选 `encoder/decoder` 仅扩展 JSON 编解码且须维持该契约。
- **检查点**：每步记录 `schema_version`、step、状态、待运行/已完成节点、已收集未合并写入、运行/状态与时间戳；写盘采用临时文件 + `os.replace` 原子写。**损坏或版本不支持的检查点返回可读错误，不静默从头运行**。
- **失败恢复**：节点失败时**保留同批次已成功节点的写入，只重跑失败节点及尚未执行节点**；成功节点的写入在批次完整后统一合并。
- **图哈希与 keep_last**：`graph_hash` 由排序后的节点/边/静态路由映射生成；恢复时哈希不匹配仅**警告**并允许继续（不承诺检测函数体变化）。`keep_last=N` 保留最近 N 个 step 检查点，默认保留全部，且不会删除恢复所需的最新检查点或 meta。

## 五、中断、人工审批与 CLI【设计】

来源：README 第 75–89 行、第 125–136 行。

- `interrupt_before=["node"]` 在目标节点执行前保存可恢复检查点；`interrupt_after=["node"]` 在其成功后保存其写入与后继。**恢复后已完成节点不会重跑**。
- `compiled.resume(run_id, *, state_update={...})`：从检查点续跑并注入人工结果（如审批通过、参数修正）。
- CLI：`run` / `resume` / `list` / `mermaid`；`--interrupt-before/after`（可重复）、`--max-steps`、`--keep-last`、`--run-id`、`--verbose`。
- **退出码**：成功 `0`；运行失败 `1`；中断/等待人工 `2`；参数错误 `2`（argparse）。`minigraph` logger 默认静默，`--verbose` 显示节点、路由与超步进度。

## 七、已知限制与范围【设计 + 边界】

来源：README 第 198–205 行、开发计划第 144–146 行。

- 节点同步、顺序执行；扇出是语义非并发。
- 运行时同步汇聚以本轮实际选中边为准，**不提供并行和外部副作用的 exactly-once 保证**——副作用（写文件、调用 API）的幂等由调用方负责。
- `mapping=None` 的动态路由编译期只给提示，运行时校验目标；**无法静态保证 END 可达**。
- 活动运行 ID 不可覆盖；`done` / `failed` 运行须显式覆盖选项归档后重建（本期未开放强制覆盖开关，冲突即报错）。

## 八、适用建议【推断，非官方声明】

基于以上【设计】与【现存实现证据】的方法论延展，供娄哥判断何时用、怎么用：

- **适合**用 MiniLangGraph 编排的任务：多步骤、有分支、需在关键网关人工把关、且怕中途崩溃要续跑的**本地 AI 工程任务**。例如：
  - DCS 设备调试流程化（采集→分析→联锁核对→人工确认→落库）；
  - 知识库入库的"提炼→核对→入库→提交"流程化；
  - 跨工具进度管理流程化（跑看板→读任务树→执行叶→刷新看板）。
- **不直接适合**（需自补）：需要自动重试、多线程并发节点、或内置调用外部服务的场景。引擎不内置这些，得节点函数自写或外部脚本编排。
- **节点内调用外部 API 的务实提醒**【推断】：因节点同步阻塞、无超时/并发兜底——① 节点内自加 `timeout`；② 失败自写 `try/retry` 或借条件路由引到重试分支（引擎只在节点**抛异常**时保留成功写入、只重跑失败节点，**不自动重试**）；③ 保证**幂等**（恢复可能重跑失败节点，有副作用操作须"重跑不重复产生坏影响"，如幂等键、先查后写）。
