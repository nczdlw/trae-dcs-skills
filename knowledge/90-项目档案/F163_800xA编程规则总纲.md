## 3. 工作流程规则

1. **分组逐一开发**：按 G 组逐个完成"校核→增量表→ST/FBD→用户确认"闭环，用户确认后才进入下一组（用户既定偏好）。
2. **基线优先**：每次开工先确认最新现场导出时间；现场已有变量/功能块一律视为已有项，不得凭旧 Excel 重复添加。
3. **增量交付**：每组只交付增量 VAR/FUN 表 + ST 代码 + FBD 管脚连接说明；增量 = 设计所需 − 现场已有。
4. **去重规则**：变量名/实例名为唯一键（忽略大小写、去首尾空格）；增量内部无重复、与现场无交集；合并后全表唯一。
5. **导入顺序**：（STRUCT 路线先建数据类型）→ VAR → PAR → FUN → 粘贴 ST → FBD 连线 → **编译整个 CementMill 程序**（非单图页）→ 保存编译日志。
6. **下载禁令**：未经接口补齐、离线编译、仿真验证和用户确认，不得在线下载（G20 已明确此禁令）。
7. **编译报已有变量**：立即从增量表移除并更新去重基线。
8. **功能块设备名注释**：Description 格式为 `英文描述 / 中文描述 - 莱歇编号`（如 `HSLM Heater / HSLM加热器 - 1632HS11.HE01`）。
9. **大逻辑用 FBD**：电机、阀门、组逻辑优先 FBD 图形实现，便于理解和查找（用户既定偏好）；ST 只做结构体初始化与布尔连锁。

## 4. 分组编程技术规则

### 4.1 每组交付物（4 件）

| 文件 | 内容 |
|---|---|
| `Gxx_..._Var.xlsx` | 组内简单变量（bool/BoolIO/dint/time/string/SignalLib.Signal） |
| `Gxx_..._Fun.xlsx` | 组内 FB 实例（GROUP1/MOTOR1/SMOTOR_PROV/SignalInReal/TP/TOf 等） |
| `Gxx_....st` | ST 纯执行代码（**无 VAR 声明段**） |
| FBD 管脚连接说明 | 需在 FBD 编辑器手动连线的管脚清单 |

### 4.2 ST 与 FBD 分工

| 职责 | 实现 |
|---|---|
| FB 实例管脚连接（GROUP1/MOTOR1/SignalInReal 等） | FBD |
| SignalInRealPar 阈值初始化（LevelH/LevelHH…逐个成员赋值） | ST |
| 布尔连锁（RS、process_lock、start_lock、O2） | ST |
| 硬件 DO 直接赋值（非 MOTOR1 管脚，如加热许可 O2） | ST |

### 4.3 功能块选型

| 设备 | 功能块 |
|---|---|
| 普通电机/加热器（DI/DO） | MOTOR1 |
| DP 通讯电机 | SMOTOR_PROV（双方向 SMOTORD_PROV） |
| 模拟量监测 | SignalInReal（SignalLib 标准库，六级报警） |
| 布尔信号监测 | SignalInBool |
| 组控制 | **GROUP1**（莱歇专用，工程内部类型；项目通用 Group 保持不动） |
| 阀门 | VALVE1 / PVALVE |
| 低/中压变频 | ABBLVVVF / ABBMVVVF |

### 4.4 MOTOR1 要点

- 三个 lock 管脚 `start_lock` / `process_lock` / `safety_lock`：**true = 锁定**，直接赋值不取反；safety_lock 经 TOf 延时并触发 Fault。
- MOTOR1 **没有 O2 管脚**；O2 是硬件 DO，逻辑与 start_lock 相反（true = 许可）。

### 4.5 SignalInReal 要点

- 连锁只用 `GTHStat`/`GTHHStat`（受 Enable 控制），不用 GTH/GTHAct。
- 温度信号只启用 H/HH，`EnableL/LL/LLL := FALSE`；压力信号按正式图启用 L/H(/HH)。
- 阈值在 ST 中初始化，**禁止**在 Var.xlsx Initial Value 列写结构体聚合（Error 1340）。
- 每个实例配套 4 个变量：`_T_IP`（SignalLib.Signal）、`_T_H`、`_T_HH`（bool）、报警名称 string。

### 4.6 GROUP1 与组接口（G10 结论）

- 从 Group 复制出 GROUP1，新增 `CON`/`COFF`（bool 输入、单周期脉冲远程启停）；禁止 `G20.Gstart_cmd` 式外部直写内部变量。
- G10 主辅机组为单级（STEP=1），`AUX_RUN = G30_RUN AND G50_RUN AND G40_ENABLED AND G55_RUN`；G10 直接读子组 `GROUP_STATUS`，不重复计算子组内部条件。
- G_start/G_stop 为 Boolean16，`.B1~.Bn` 按序对应组内设备。

### 4.7 命名规则

- 变量：`N<节点>_<系统>_<设备>_<信号>_<后缀>`（如 `N562_HD1_T1_T_H`）；后缀：`_RS`/`_PL`/`_SL`/`_O2`/`_T_IP`/`_T_H`/`_T_HH`/`_P_IP`/`_P_H`，结尾 `N` 为报警名称 string。
- FB 实例：`N<节点><系统><设备类型><编号>`（如 `N562HD1E01`）。
- **变量名用设计院编号（N562_…），Description/注释标莱歇编号（1632…）**，映射维护在 `Cement Mill IO List.xlsx` / `CementMill_设备信号映射表.xlsx`。
- 同程序内各组共享变量作用域：一个变量只在一个组的 Var.xlsx 定义，其他组直接引用。

## 5. ST 编码与编译规则（错误防治）

1. 硬件 I/O 类型（DintIO/RealIO/DwordIO）必须经 `.Value` 访问（Error 1030 为最常见错误）。16-bit→DwordIO 需 DWORD_TO_DINT 转换；32-bit→DintIO/RealIO 直接用。
2. Code 只放执行代码：无 `FUNCTION_BLOCK`/`VAR`/`END_VAR`（Error 1116）。
3. 禁止位运算 `AND/OR/SHR`：用 `/2^n MOD 2` 解包、IF 累加打包（Error 1055/1108）；Bit31 打包用 `- 2147483647 - 1`。
4. 禁止字符串/时间字面量：放 Var 表 Initial Value（string 用英文单引号）。
5. FB 实例声明在 Fun 表（类型名大小写敏感：`TOf`、`R_Trig`、`AlarmCond`…）；Fun 表实例必须在 Code 中被调用（Warning 1542）。
6. 引脚名大小写敏感：`R1`（RS 复位）、`Reset`（SR）、`In`、`Clk`；简单 FB 调用单行；多参数 FB 无尾随逗号、`);` 不独行。
7. `in_out` 不带 retain（Error 1005）；`in` 参数不赋值（Error 1034）；VAR+PAR 合并后名称唯一（Error 1000，大小写不敏感）。
8. DP 地址表是 WORD 编号非字节偏移；Release bit（控制字 bit3）恒置 1；传动换算：频率 20000=100%、电流/功率/温度 10=1 单位。
9. 报警用 AlarmCond（Severity 800 重报警/500 警告，不支持 CondName）；事件用 SimpleEventDetector（停止事件需手动反逻辑 + prev_running 末尾更新）。

### 6.2 连锁类型与全局架构

- 连锁类型：STAITL（启动）/OPITL（操作）/PRTITL（保护）/PSTITL（保护性启动）/PQSTOP（过程快速停止）。
- PQSTOP 来源（OR）：MGB 保护、磨机振动 HH、主电机保护、磨机风机保护 → 停主电机、风机、喷淋、原料喂料。
- 启动顺序：AUX（润滑/液压/密封风）→ GC 气体回路（过滤器/选粉机/挡板/风机）→ MD 主电机（需 AUX_RUN+GC_RUN+RJ_RUN+辊已提升+润滑 OK）→ RMF 原料喂料（需 MD_RUN+PRO_DATA_OK；带动回转给料、润滑脂、喷淋、助磨剂）。
- 加热器统一模式：`TI01 < L1 AND 16xx:HEATER_ENABLED → HE01:ON（延时 5 秒）`；温度 H/HH 迟滞 RS + process_lock/start_lock + O2 四层（见 4.4/4.5）。
