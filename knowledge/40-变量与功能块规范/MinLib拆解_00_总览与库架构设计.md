# 00 总览与库架构设计

> 本文件是《MinLib功能块拆解与自定义库复用设计》套件的入口和索引。先读本文件，再按需查 01~09。

## 2. MinLib 已核实事实清单（拆解的源头）

### 2.1 库的定位与核心机制【核实，数据表 p2】

- MinLib = 一套**面向对象的软件控制模块**（object-oriented software control modules），目标是"高效、全参数化"地设计过程控制和电气应用，把块与块之间传统上靠代码硬连的活，变成**参数化配置**。
- 核心机制叫 **Control Connection（控制连接）**：父子对象之间一条逻辑连接，是一条"**数据高速公路**"，父对象发命令、子对象报状态，**双向**；运行时可以改变这条连接上交换的信息量。替代了传统"一个信号一根线"的散乱连线（数据表 Figure 2 vs Figure 3）。
- 效益（数据表 p5）：对象间个性化代码降到传统应用的 **10%**。

### 2.2 三大功能区【核实，数据表 p2】

| 功能区 | 缩写 | 干什么 |
|---|---|---|
| 组/顺序控制 | GCC | 组控、顺序/周期启停、路由、主备（duty standby） |
| 过程设备联锁 | PCC | 电机/阀门等设备的所有联锁信号参数化管理 |
| 电能管理 | EEM | 断路器控制、功率因数补偿、电量/负荷限值调度（含超限预警和甩负荷） |

### 2.3 组/顺序控制（GCC）功能清单【核实，数据表 p2】

- 连续或周期过程的组控制模块；
- 每组设备数量不限（电机、阀门、执行器、回路都可以挂）；
- 按**参数化顺序**启停组内全部设备；
- selector 模块做参数化**路由**和**主备**；
- 一个设备可以同时挂到**多个组**（一个子对象多个父对象）；
- 组内设备汇总状态（run/warning/failure）显示在组头流程画面和组面板上；
- **首报检测（first fault detection）**：导致组失败的设备 tag 直接显示在组面板上，带超链接一键跳到故障设备；
- 设备面板上能看到本设备的关键参数：组名、步号、启停延时、路由信息；
- **组状态 viewer**：展示组和全部设备的详细信息，含启动顺序和路由；
- **运行时可改**：增/删/改设备启停顺序和路由，下载后 viewer 自动更新。

### 2.4 过程设备联锁（PCC）功能清单【核实，数据表 p4】

- 每台设备的全部联锁信号都接到"联锁控制连接"上；**信号软件模块的参数**决定联锁行为；
- 模拟量信号、数字量信号、PID 回路模块都能配置"控制联锁"和"自动过程启停"（一个信号可启停一台或多台设备）；
- 每台设备的信号数量不限；
- 信号会读设备状态（运行/停止/本地/检修）来决定是否执行报警和启动禁止；
- 首报检测 + **抑制后续不必要报警**；
- 引发故障的信号 tag 自动显示在设备面板上，带超链接跳到故障信号；
- 信号面板显示：阈值、报警延时、故障延时、联锁类型、本地 override、启动禁止时间；
- **联锁 viewer**：一台设备的全部信号一览（无联锁/警告/故障），并显示维修或异常情况下做的临时 override；
- **运行时可改**联锁，viewer 自动更新。

### 2.5 报警管理规则【核实，数据表 p5】

报警清单消息在以下情况**抑制**（不弹给操作员）：
1. **父对象是停止的**——只报"活动父对象"下的报警；
2. **父对象正在启动**——启动报警抑制期（躲开启动瞬态）；
3. **父对象在本地控制模式**——本地操作时自动确认。

另外：
- **首报 + 最高优先级报警**检测，并转发到 consumer（设备）和 group（组）；
- 定义为 **standby（备用）的 consumer 自动降低报警严重度**；
- 2019 新版进一步：按过程状况自动降低报警严重度，报警信息用**形状+颜色冗余编码**（不只靠颜色）【核实，ABB 官网 2019 新闻稿】。

### 2.6 仿真与调试【核实，数据表 p5 + ABB 官网 2019】

- **内置仿真（built-in simulation）跑在 soft controller 上**：测试和操作员培训用；
- 软件块带**内置仿真模式**；
- **commissioning check framework（调试检查框架）**：缩短调试时间、跟踪现场调试进度、保证升级演进【核实，ABB 官网产品页】；
- 2019 新版明确**配合 800xA 6.1 平台**发布【核实，ABB 官网新闻稿】，全球 450+ 水泥/矿山现场在用。

### 2.7 HMI/面板设计原则【核实，数据表 p5 + 官网 2019】

- 状态指示用**颜色+形状+标签三重编码**，不只靠颜色（考虑色弱和异常聚焦）；
- 画面设计聚焦异常工况；
- 父子面板**双向动态超链接**；
- 组状态 viewer / 联锁 viewer / 设备诊断 viewer；
- 新版 7 套主题、faceplate 父子双向链接、viewer 内直接导航。

## 3. 自定义库三层架构【自拟，依据 2.1~2.7 设计】

给你自己的库取名 **`CEMENT_LIB`**（下称"CL 库"，版本 1.0）。整体三层：

```
┌─────────────────────────────────────────────────────────────┐
│ 第3层 面板层（Aspect Objects）                                 │
│   FP_Motor / FP_Valve / FP_Group / FP_Signal                  │
│   + 组状态 Viewer + 联锁 Viewer                                │
│   （800xA  Workplace / Plant Explorer 的 Aspect 对象）          │
├─────────────────────────────────────────────────────────────┤
│ 第2层 功能块层（Function Block Types，FBD 为主）                │
│   MOTOR_C   电机（开关型动力设备通用）                          │
│   VALVE_C   阀门（开关阀/调节阀双模式）                         │
│   GROUP_C   组（顺序/周期/首报/汇总）                           │
│   SEL_C     选择器（主备/路由）                                 │
│   SIG_C     信号联锁（DI/AI/PID 输出联锁量）                    │
│   CHK_C     调试检查框架块                                      │
├─────────────────────────────────────────────────────────────┤
│ 第1层 接口层（Control Connection = 结构化数据类型）             │
│   CC_Equip   组→设备 / 设备→组 双向接口                         │
│   CC_Signal  信号→设备 联锁接口                                 │
│   CC_Group   组→组 / 组→系统 汇总接口                           │
└─────────────────────────────────────────────────────────────┘
```

三层关系一句话：**第 1 层定"说什么"，第 2 层定"怎么算"，第 3 层定"怎么看"**。工程里只做两件事：拖 FBT 实例、连 CC 管脚。所有行为差异用参数配，不改代码。

### 3.1 为什么用 STRUCT 实现 Control Connection【自拟】

MinLib 的控制连接是一条"数据高速公路"【核实，数据表 p2】。800xA Control Builder 里没有原生"控制连接"对象给你直接调，最接近的落地方式就是**结构化数据类型（STRUCT）**：

- 每条 CC 是一对 STRUCT 变量：父侧一个 `out`、子侧一个 `in_out`（或父 `out`/子 `in` + 子 `out`/父 `in` 两组）；
- 传统做法：组和电机之间拉 15 根散线（命令/允许/状态/故障/步号/延时…），80 个 FB 的项目就是 1000+ 根线，错一根查三天；
- CC 做法：1 根"结构体线"传全部信息，接口变动只改 STRUCT 定义，不动 FBD 连线；
- 运行时改信息量：STRUCT 里预留备用字段/数组，改参数即可扩展。

FBD 里 STRUCT 管脚可以整体连线，也可以展开到成员逐个连（排查时用）。

### 3.2 与 F163 现有 TAYNINH_LIB 的差异【自拟，依据 F163 规则总纲 §1/§4】

F163 现场库（TAYNINH 1.0.3，约 80 个 FB）里有 MOTOR1、SMOTOR_PROV、Group、GROUP1、VALVE1/PVALVE、SignalInReal。CL 库不是替换它们，是**下一代的模板化升级**，差异对照：

| 维度 | 现有 TAYNINH_LIB | CL 库（本套件设计） |
|---|---|---|
| 组→设备接口 | 散变量（G_start/G_stop Boolean16、GROUP_STATUS 直读）【F163 §4.6】 | CC_Equip 结构体单线传递【自拟】 |
| 联锁 | 代码里硬写 RS/process_lock 赋值【F163 §4.4】 | SIG_C 参数化联锁 + 联锁 viewer【自拟，参照数据表 p4 核实功能】 |
| 报警 | AlarmCond 实例散落在工程 Code 里【F163 §5.9】 | 报警内嵌 FBT，抑制/首报/降级在库内闭环【自拟，规则依据数据表 p5 核实】 |
| 仿真 | 无统一机制 | En_Sim + Sim_* 参数，硬件输出屏蔽【自拟，依据数据表 p5 核实】 |
| 调试 | 人工清单 | CHK_C 检查状态机 + 组级进度【自拟，依据官网 2019 核实】 |
| 面板 | 项目画面逐个画 | FP_* Aspect 模板 + 父子超链接【自拟，依据官网 2019 核实】 |
| 顺序调整 | 改代码/改连线 | 改 StepNo 参数即改顺序【自拟，参照数据表 p2 核实功能】 |

迁移策略：老项目继续用旧库不动；新组（如新增控制器）直接用 CL 库做，跑通一个组再推广。**不要动现场已编译下载的 CementMill 程序**【F163 §3.6 下载禁令】。

## 5. 一句话结论

MinLib 值钱的不是那几个功能块，是四样东西：**①控制连接（一条结构化总线代替散线）②参数化（改参数不改代码）③报警抑制与首报（让操作员只看该看的）④仿真+调试框架（上线前把问题在 soft controller 上暴露完）**。CL 库就是把这四样按 800xA 6.1.0 + F163 规则复刻一遍。
