# PLC_ST编程检查与命名参考（GitHub开源实践）

> 来源：2026-09-14 GitHub电气自动化项目调研（详见 [70-工具与工作方法/GitHub电气自动化项目调研报告_20260914](../70-工具与工作方法/GitHub电气自动化项目调研报告_20260914.md)）
> 适用性声明：以下内容提炼自 TwinCAT/CODESYS 生态的开源实践，**非 ABB 800xA 官方规范**。800xA 工程现行规则以 [90-项目档案/F163_800xA编程规则总纲](../90-项目档案/F163_800xA编程规则总纲.md) 为准，本参考仅作补充对照——两者冲突时以总纲为准。
> 溯源说明：标【PLCopen xx】的条目对应 PLCopen 编码指南条款号（经 plc-st-review presets/plcopen.yml 注释核实）；标【约定】的是社区实践惯例（OSCAT/TcUnit），无标准条文依据，采用前自行核实。

## 一、静态检查清单（ST/FBD 通用，按类分组）

### 1. FB 实例完整性（最常见坑）

| 检查项 | 说明 | 来源 |
|---|---|---|
| 实例只读输出从未调用 | 读 T1.Q 不调 T1() 永远拿到初值 | plc-st-review FB_INSTANCE_NEVER_CALLED |
| 同一实例一周期双调 | 一个扫描周期调用两次同一实例 | plc-st-review FB_INSTANCE_DOUBLE_CALL【PLCopen CP20】 |
| 边沿触发器实例复用 | 同一 R_TRIG/F_TRIG 实例接多个不同 CLK 输入 | plc-st-review EDGE_TRIG_REUSED |
| 定时器 PT=T#0s | TON/TOF/TP 计时值为零 | plc-st-review TIMER_PT_ZERO |
| 定时器未驱动 | 读了 Q/ET 却没人给 IN 赋值 | plc-st-review TIMER_NOT_DRIVEN |
| SR/RS 选用与意图不符 | 双稳态块选用与变量名/注释意图矛盾 | plc-st-review BISTABLE_DOMINANCE_MISMATCH |

### 2. 逻辑完整性

除零；字面量数组下标越界；WHILE TRUE 无退出；循环边界颠倒（TO 值小于 FROM）；未初始化变量使用；一个全局变量被多个 PROGRAM 写。

### 3. PLCopen 对齐组

| 检查项 | 条款 |
|---|---|
| 禁用 GOTO/EXIT/CONTINUE | 【PLCopen L10】 |
| 每个 IF 有 ELSE | 【PLCopen L17】 |
| POU 必须有注释 | 【PLCopen C2】 |
| 参数过多（默认上限 8） | 【PLCopen CP23】 |
| 单 POU 引用全局变量过多（默认上限 10） | 【PLCopen CP18】 |
| 隐式类型转换 | 【PLCopen CP25】 |
| TIME 类型做等值比较 | 【PLCopen CP28】 |
| 直访硬件地址 %Ix.x | 【PLCopen N1/CP1】 |

### 4. 安全（IEC 62443 映射）

硬编码凭据（CR 1.5）；硬编码网络端点（SI-1）；VAR_INPUT 未做范围校验就当数组下标/除数（CR 3.5）；调试 pragma 留在生产代码（SI-2）；明文持久化密钥（CR 4.1）。

### 5. 团队配置驱动

命名规范检查（前缀表可配置）；禁用符号黑名单（已废弃变量名防复活）。

## 二、AI 改动后的回归核对项（diff-based 思路）

- 管脚/POU 签名变更 → 所有调用点是否同步（含 VAR/FUN 表与操作员画面引用）
- 常量/设定值变更 → 名字含 SAFETY_/INTERLOCK_/SIL_ 前缀的自动提级复核（plc-st-review 安全前缀机制）
- 定时值 PT 变更 → 按变化倍数分级：≥2x 警告、≥10x 错误（plc-st-review TIMER_VALUE_CHANGED 源码用 log10 比率）
- 变量类型变更 → 是否影响读点/DP 报文映射
- 枚举增删值 → CASE 分支是否补齐

## 三、命名参考（OSCAT 541 个 POU 实测约定）

- **家族前缀**：CTRL_（控制器）/ FT_（滤波传递）/ GEN_（信号发生）/ FF_（触发器）/ ESR_（事件记录）【约定】
- **数字后缀 = 通道数/深度**：INTERLOCK_4、FIFO_16、SEQUENCE_64【约定】
- **字母后缀 = 变体**：W=窗口、L=限幅（如 FT_PIW / FT_PIDWL）【约定】
- **下划线开头 = 内部辅助块**（事实私有）：_RMP_B、_BUFFER_CLEAR【约定】
- **管脚名字典**（控制类块全大写工艺缩写）【约定】：

| 管脚 | 含义 | 管脚 | 含义 |
|---|---|---|---|
| ACT | 实际值 | RST | 复位 |
| SET0 | 设定值 | E | 使能 |
| MAN / M_I | 手动 / 手动值 | MODE | 模式选择 INT（头注释逐值说明） |
| TP | 单周期脉冲标志 | Y | 模拟输出 |
| Q / Q1..Q4 | 布尔输出 | LIM | 限幅标志 |
| KP / TN / TV | PID 参数 | LL / LH | 输出下/上限 |

- 800xA 映射：设备功能块命名以 F163 总纲规则为准，本字典作管脚语义对照用

## 四、FB 头注释与修订历史模板（OSCAT 格式）

```
(*
version 1.0    2026-09-14
programmer     <编制人>
tested by      <校核人>
<功能描述：干什么、怎么用、参数含义、边界行为>
*)
<实现代码>
(* revision history
<作者> <日期>  rev 1.1
    <逐条改动说明>
*)
```

与 800xA 侧"功能块设备名注释 = Loesche 编号"规则并用；rev 号与 VAR/FUN 表版本字段对应。

## 五、断言/复核记录三段式（TcUnit）

- 失败消息固定格式：`FAILED '<用例路径>', EXP: <期望>, ACT: <实际>, MSG: <说明>`
- 浮点/数值比对必须带容差（Delta）：|EXP−ACT| > Delta 才算失败
- 用例自解释命名（完整句式，如 MotorStartInterlocksTripIn3s）；禁用用例名前加 `disabled_` 前缀而非删代码
- 结果三级模型：用例级 → 套件级（按设备 FB 分组）→ 总表

## 六、IO 点表→FB 映射四步法（IO-AutoMapper）

1. 行解析为含 **Excel 行号**的 JSON（行号用于结果回写原表）
2. 信号四分类（AnalogIn / AnalogOut / DigitalIn / DigitalOut）
3. **同设备所有信号归并到同一 FB**（prompt 硬规则）
4. 逐信号映射 FB 参数，匹配依据 = "功能意图 → 方向 → 类型"，无匹配输出 n/a（禁止编造）

- 配置驱动适配异构点号表：每类表一个配置对象（列名 / 信号列 / 描述列 / 位号正则 / 起止行），不写死格式
- ground truth 对账：准备人工映射基准表，自动比对出对账报告（正确/错误清单）

## 七、AI 辅助 DCS 编程操作对照表（twincat-agent 思路，800xA 适配）

| 操作 | 应该 | 禁止 |
|---|---|---|
| 查库块管脚/系统变量 | 查工程导出/规格表/手册 | 凭模型记忆猜签名 |
| 修改工程数据 | 走 VAR/FUN 导入表流程 | 直接改 Control Builder 导出物 |
| 引用外部资料数据 | 注明页码/来源 | 编造数值 |
| 操作失败 | 有界重试→诊断→升级用户 | 无限循环重试 |
