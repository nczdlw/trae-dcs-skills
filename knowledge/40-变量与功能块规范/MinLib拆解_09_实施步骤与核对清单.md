# 09 实施步骤与核对清单

> 按本篇走，从空库到新组上线。每步做完打勾，打不了勾就停在原地排查，别带着问题上下一步。

## 1. 总体路线（七步，每步一道门禁）

```
① 建库+STRUCT → ② FBT 骨架 → ③ 编译通过 → ④ Aspect 面板
 → ⑤ 软仿真 FAT → ⑥ 选一个新组试点 → ⑦ 推广 + 老组评估
```

| 步 | 内容 | 门禁（不过不进下一步） |
|---|---|---|
| ① | Control Builder 建 CEMENT_LIB 1.0.0；按 01 文档 §2 建 4 个 STRUCT（CC_EqCmd/CC_EqStat/CC_SigOut/CC_SigIn+CC_Group） | 数据类型编译无错；字段与 01 文档逐行对过 |
| ② | 建 MOTOR_C/GROUP_C FBT，抄 08 文档骨架 | FBT 编译通过；§5 自检表全过 |
| ③ | 工程里建测试程序：2 个 MOTOR_C + 1 个 GROUP_C + 2 个 SIG_C | 整程序编译 0 error；Warning 逐条看过 |
| ④ | 按 05 文档 §8 建 FP_Motor/FP_Group Aspect，绑管脚 | 每实例面板能开；按钮能点；参数能改 |
| ⑤ | soft controller 上仿真 FAT：跑 07 文档 §1.3 四课 + §3 六步流程 | 四课期望现象全中；检查卡全 PASS |
| ⑥ | 现场选一个**新组**（不动 CementMill），真信号重跑 C1~C10 | 真机全 PASS；viewer 调试列全 ✓ |
| ⑦ | 同法铺开其余新组；老组是否切换单独评估 | 每组过⑥门禁才接下一步 |

## 2. 分步核对清单

### ① 建库与 STRUCT

- [ ] 库名 CEMENT_LIB，版本 1.0.0，注释写明依据文档号

- [ ] CC_EqStat 15 字段与 §2.2 一致
- [ ] CC_SigOut 11 字段 / CC_SigIn 5 字段 / CC_Group 8 字段与 §2.3-2.5 一致
- [ ] String 字段长度统一 [32]/[40]
- [ ] **STRUCT 先于 FBT 建**（F163 §3.5 顺序）

- [ ] MOTOR_C：VAR_INPUT/OUTPUT/VAR 分区与 08 文档 §1 一致

## 3. 800xA 编译错误速查（F163 §5 实战）

| 错误码 | 含义 | 常见原因 | 解法 |
|---|---|---|---|
| 1030 | 硬件型访问方式错 | DintIO 没走 .Value | 全部 .Value 访问 |
| 1116 | Code 里有声明段 | 工程 Code 混入 VAR/FB | Code 只放执行语句 |
| 1055/1108 | 位运算 | AND/OR/SHR 用在整型 | /2^n MOD 2 解包、IF 累加打包；Bit31 用 -2147483647-1 |
| 1000 | 名称重复 | VAR+PAR 合并后重名 | 大小写不敏感查重 |
| 1005 | in_out 带 retain | CC 结构体标了 retain | 去掉 retain |
| 1034 | in 参数被赋值 | 往输入管脚写值 | 输入只读 |
| 1340 | 结构体聚合初值 | Var 表 Initial Value 写结构体 | 初值留空，ST 初始化段逐个成员赋值 |
| 1542 | 实例未被调用 | 声明了没用 | 删除或补调用 |
| 编译报"已有变量" | 与现场重复 | 增量表没去重 | 按 F163 §3.7 移除并更新去重基线 |

## 5. 本篇结论

实施节奏：**库里求稳（①②③门禁），软仿真求全（⑤），现场求慢（⑥⑦）**。所有 U 项实测结果回来一条，把对应文档的【需实测确认】销掉一条——文档会越用越准。
