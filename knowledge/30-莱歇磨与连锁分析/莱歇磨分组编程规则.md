# 莱歇磨 LM46.2+2 分组编程规则

> **项目**: 越南 F163 水泥粉磨站 | **系统**: ABB 800XA + logi.cals IEC 61131-3 | **设备**: Loesche LM46.2+2 CSD 立磨
> **程序**: `NINH_3E8_2R1.LoescheMill`
> **适用范围**: G10/G20/G30/G40/G50/G60 等分组编程

---

## 1. 分组编程交付物

每个功能组 (Gxx) 交付 4 个文件:

| 文件 | 说明 |
|------|------|
| `Gxx_xxx_Var.xlsx` | 变量表: 声明组内所有简单变量 (bool/dint/time/string/BoolIO 等) |
| `Gxx_xxx_Fun.xlsx` | 功能块表: 声明组内所有 FB 实例 (GROUP/MOTOR1/SMOTOR_PROV/SignalInReal/TP/TOf 等) |
| `Gxx_xxx.st` | ST 代码: 结构体初始化 + 布尔逻辑 (无 VAR 声明段) |
| `FBD管脚连接清单.html` | FBD 连接指南: 列出所有需在 FBD 编辑器中手动连接的管脚 |

---

## 2. 架构分工: ST vs FBD

| 职责 | 实现方式 | 说明 |
|------|---------|------|
| 功能块实例管脚连接 | **FBD** | GROUP/MOTOR1/SMOTOR_PROV/SignalInReal 的管脚在 FBD 编辑器中连线 |
| SignalInRealPar 阈值初始化 | **ST** | LevelH/LevelHH/LevelL 等在 ST 中逐个成员赋值 |
| 布尔连锁逻辑 | **ST** | RS 触发器、process_lock、start_lock、O2 等逻辑运算 |
| 硬件 DO 直接赋值 | **ST** | 非 MOTOR1 管脚的 DO 信号 (如 O2 Heater Start Permit) 在 ST 中赋值 |

**核心原则**: ST 代码只包含可执行逻辑, **不包含 VAR 声明段** — 变量声明由导入 Var.xlsx/Fun.xlsx 自动生成。

## 3. 变量表 (Var.xlsx) 规则

### 3.1 允许的变量类型

| 类型 | 用途 | 示例 |
|------|------|------|
| `bool` | 内部状态 (RS 触发器等) | `N562_HD1_E01_RS` |
| `BoolIO` | 硬件 DI/DO 或 MOTOR1 管脚中间变量 | `N562_HD1_E01_PL` |
| `time` | 定时器预设值 | `T#30M` |
| `string` | 报警名称等 | `N562HD1T1N` |
| `SignalLib.Signal` | SignalInReal 的 InteractionPar | `N562_HD1_T1_T_IP` |
| `Boolean16` | GROUP 的 G_start/G_stop | `G20_ST` |

### 3.2 禁止事项

- **禁止**在 Var.xlsx 中声明功能块实例 (用 Fun.xlsx)
- **禁止**在 Initial Value 列使用结构体聚合语法 (如 `LevelH:=60.0` → 会报 Error 1340)
- **禁止**在 Var.xlsx 中重复定义 IO 表已有的变量

### 3.3 变量命名规范

```
N<节点>_<系统>_<设备>_<信号>_<后缀>

示例:
N562_HD1_E01_PL    → HSLM加热器E01的process_lock (BoolIO)
N562_HD1_E01_RS    → HSLM加热器E01的RS触发器状态 (bool)
N562_HD1_T1_T_IP   → HSLM温度T1的InteractionPar (SignalLib.Signal)
N562_HD1_T1_T_H    → HSLM温度T1的H报警状态 (bool, 来自GTHStat)
N562_HD1_T1_T_HH   → HSLM温度T1的HH报警状态 (bool, 来自GTHHStat)
N562HD1T1N         → HSLM温度T1的报警名称 (string)
```

后缀含义:

| 后缀 | 含义 | 类型 |
|------|------|------|
| `_RS` | RS 触发器状态 | bool |
| `_PL` | process_lock 中间变量 | BoolIO |
| `_SL` | start_lock 中间变量 | BoolIO |
| `_O2` | 硬件 DO 启动许可 | BoolIO (IO 表定义) |
| `_T_IP` | 温度 InteractionPar | SignalLib.Signal |
| `_T_H` | 温度 H 报警状态 (GTHStat) | bool |
| `_T_HH` | 温度 HH 报警状态 (GTHHStat) | bool |
| `_P_IP` | 压力 InteractionPar | SignalLib.Signal |
| `_P_H` | 压力 H 报警状态 (GTHStat) | bool |
| `N` (结尾) | 报警名称字符串 | string |

## 5. MOTOR1 功能块详解

### 5.1 管脚定义 (从 MOTOR1_PAR.xlsx 确认)

**输入管脚 (IN):**

| 管脚 | 类型 | Initial | 说明 |
|------|------|---------|------|
| Description | string[80] | - | 设备描述 |
| Ready | bool | - | 就绪反馈 (DI) |
| Running | bool | - | 运行反馈 (DI) |
| Emg_stop | bool | - | 急停信号 |
| Group_start | bool | - | 组启动 (来自 GROUP 的 G_start.Bx) |
| Group_stop | bool | - | 组停止 (来自 GROUP 的 G_stop.Bx) |
| Local_start | bool | - | 本地启动 |
| **start_lock** | bool | **true** | 启动锁定 (true=锁定, 阻止启动) |
| **process_lock** | bool | **true** | 过程锁定 (true=锁定, 运行中停止) |
| **safety_lock** | bool | **true** | 安全锁定 (true=锁定, 经 TOf 延时) |
| speedswitch | bool | - | 速度开关 |
| ext_fault | bool | - | 外部故障 |
| LOCAL | bool | - | 本地/远程模式 |

**输出管脚 (OUT):**

| 管脚 | 类型 | 说明 |
|------|------|------|
| Drive | bool | 驱动输出 (→ 硬件 DO) |
| Fault | bool | 故障输出 |

**注意: MOTOR1 没有 O2 管脚。**

### 5.2 三个 Lock 管脚逻辑

三个 lock 管脚都是 **Initial: true**, 即 **true = 锁定/阻止**:

| 管脚 | 作用时机 | 逻辑 |
|------|---------|------|
| `start_lock` | 启动时 | true → 阻止新启动 (已运行的设备不受影响) |
| `process_lock` | 运行中 | true → 停止运行中的设备 |
| `safety_lock` | 安全连锁 | true → 经 TOf 延时后停止 + 触发 Fault |

**赋值规则: 锁定信号直接赋 true, 允许赋 false。** 不要取反。

### 5.3 MOTOR1 变量定义 (Var.xlsx)

| 变量名 | 类型 | 用途 |
|--------|------|------|
| `N562_HD1_E01_D` | BoolIO | Description (保留) |
| `N562_HD1_E01_RD` | BoolIO | Ready (DI, IO 表定义) |
| `N562_HD1_E01_R` | BoolIO | Running (DI, IO 表定义) |
| `N562_HD1_E01_O1` | BoolIO | Drive 输出 (DO, IO 表定义) |
| `N562_HD1_E01_PL` | BoolIO | process_lock (Var 定义, ST 赋值) |
| `N562_HD1_E01_SL` | BoolIO | start_lock (Var 定义, ST 赋值) |
| `N562_HD1_E01_RS` | bool | RS 触发器内部状态 (Var 定义) |

## 6. SignalInReal 功能块详解

### 6.1 管脚分类

**核心信号:**

| 管脚 | 方向 | 类型 | 说明 |
|------|------|------|------|
| `Name` | IN | string[30] | 报警对象名称 |
| `In` | IN_OUT | RealIO | AI 模拟量输入 (硬件配置创建) |
| `Out` | OUT | real | 标准化工程值输出 |
| `InteractionPar` | IN_OUT | SignalInRealPar | 交互参数结构体 (阈值在此设置) |

**六级报警输出管脚 (以 H 级为例):**

| 管脚 | 方向 | 说明 |
|------|------|------|
| `GTH` | OUT | 当前值 > LevelH 的**纯比较结果** (不受 Enable 控制) |
| `GTHStat` | OUT | H 报警**状态** (受 Enable 控制, 不受 Inhibit 控制) |
| `GTHAct` | OUT | H 报警**动作** (受 Enable 和 Inhibit 双重控制) |

**GTH / GTHStat / GTHAct 区别:**

```
当前值 > LevelH?
    │
    ├─→ GTH (纯比较, 不受任何控制)
    │
    └─→ EnableH = TRUE?
         ├─ FALSE → GTHStat = FALSE, GTHAct = FALSE
         └─ TRUE  → GTHStat = TRUE (报警状态)
                     │
                     └─ InhGTHAct = FALSE?
                          ├─ TRUE  → GTHAct = FALSE (动作被抑制)
                          └─ FALSE → GTHAct = TRUE (报警动作)
```

**项目约定: 连锁逻辑使用 `GTHStat` (受 Enable 控制, 不使用 GTH 或 GTHAct)。**

### 6.2 InteractionPar 结构体 (SignalInRealPar)

阈值在 ST 代码中初始化, **不在** Var.xlsx 的 Initial Value 列设置:

```pascal
(* 温度: H/HH 报警, 禁用 L/LL/LLL *)
N562_HD1_T1_T_IP.LevelH    := 60.0;
N562_HD1_T1_T_IP.LevelHH   := 65.0;
N562_HD1_T1_T_IP.EnableL   := FALSE;
N562_HD1_T1_T_IP.EnableLL  := FALSE;
N562_HD1_T1_T_IP.EnableLLL := FALSE;
```

```pascal
(* 压力: L/H/HH 报警 *)
N562_LQ1_P01_T_IP.LevelL    := 0.5;
N562_LQ1_P01_T_IP.LevelH    := 1.5;
N562_LQ1_P01_T_IP.EnableHH  := FALSE;
N562_LQ1_P01_T_IP.EnableHHH := FALSE;
N562_LQ1_P01_T_IP.EnableLL  := FALSE;
N562_LQ1_P01_T_IP.EnableLLL := FALSE;
```

### 6.3 SignalInReal Var.xlsx 变量定义

每个 SignalInReal 实例需要 4 个变量:

| 变量名 | 类型 | 说明 |
|--------|------|------|
| `N562_HD1_T1_T_IP` | SignalLib.Signal | InteractionPar (Initial Value 留空, retain, hidden) |
| `N562_HD1_T1_T_H` | bool | H 报警状态 (← GTHStat) |
| `N562_HD1_T1_T_HH` | bool | HH 报警状态 (← GTHHStat) |
| `N562HD1T1N` | string | 报警名称 |

## 7. GROUP 功能块详解

### 7.1 关键管脚

| 管脚 | 方向 | 类型 | 说明 |
|------|------|------|------|
| `STEP` | IN | int | 组内设备数 |
| `run_1` ~ `run_n` | IN | bool | 各设备运行反馈 (DI .Value) |
| `Emg_stop` | IN | bool | 急停信号 |

```pascal

G20_ST.B3  → N562LQ3E01.Group_start   (* 3# 设备 *)
G20_ST.B4  → N562LQ1E01.Group_start   (* 4# 设备 *)
```

## 8. 温度监测连锁模式 (G20 加热器组)

### 8.1 连锁架构

温度连锁通过**四个层次**实现:

```
┌─────────────────────────────────────────────────────┐
│ 1. RS 触发器 (滞回控制)                               │
│    置位: NOT H AND NOT HH (温度 < SL1)               │
│    复位: HH (温度 > SH1)                             │
│    → 提供温度在 H~HH 之间的回差保护                   │
├─────────────────────────────────────────────────────┤
│ 2. process_lock (过程锁定, MOTOR1 管脚)              │
│    PL = (NOT RS) OR (NOT LS)                        │
│    → 温度超 HH 未恢复 OR 液位低 → 锁定停止            │
├─────────────────────────────────────────────────────┤
│ 3. start_lock (启动锁定, MOTOR1 管脚)                │
│    SL = H                                           │
│    → 温度超 H 时阻止新启动 (true=锁定)                │
├─────────────────────────────────────────────────────┤
│ 4. O2 硬件 DO (启动许可, 非 MOTOR1 管脚)              │
│    O2 = NOT H                                       │
│    → 温度超 H 时硬件许可信号断开                      │
└─────────────────────────────────────────────────────┘
```

### 8.2 ST 代码模板

```pascal
(* === 1. SignalInRealPar 阈值初始化 === *)
xxx_T_IP.LevelH    := <H值>;
xxx_T_IP.LevelHH   := <HH值>;
xxx_T_IP.EnableL   := FALSE;
xxx_T_IP.EnableLL  := FALSE;
xxx_T_IP.EnableLLL := FALSE;

(* === 2. RS 触发器 (滞回) === *)
IF (NOT xxx_T_H) AND (NOT xxx_T_HH) THEN
    xxx_RS := TRUE;    (* 温度 < H, 置位 *)
ELSIF xxx_T_HH THEN
    xxx_RS := FALSE;   (* 温度 > HH, 复位 *)
END_IF;

(* === 3. process_lock === *)
xxx_PL.Value := (NOT xxx_RS) OR (NOT xxx_LS.Value);

(* === 4. start_lock + O2 === *)
xxx_SL.Value := xxx_T_H;          (* true=锁定 *)
xxx_O2.Value := NOT xxx_T_H;      (* true=许可 *)
```

### 8.3 关键规则

- 温度监测**只用 H/HH 报警**, L/LL/LLL 必须禁用 (项目约束)
- RS 触发器使用报警状态 (GTHStat/GTHHStat), 不引用温度实时值
- process_lock = **true 表示锁定** (与 MOTOR1 管脚定义一致)
- start_lock = **true 表示锁定** (H 报警时锁定启动)
- O2 = **true 表示许可** (逻辑与 start_lock 相反, 因为是硬件 DO)
- RS 触发器状态变量用 `bool` 类型, process_lock/start_lock 用 `BoolIO` 类型

## 10. DP 通信电机 (SMOTOR_PROV) 模式

### 10.1 SMOTOR_PROV vs MOTOR1

| 特性 | MOTOR1 | SMOTOR_PROV |
|------|--------|-------------|
| 通信方式 | 硬件 DI/DO | Profibus DP |
| 控制字 | 无 | Control Word (位打包) |
| 状态字 | 无 | Status Word (位打包) |
| 适用设备 | 加热器/简单电机 | 变频器/软启动器电机 |

### 10.2 DP 通信规则

- 32 位数据只能转为 Int32→DInt (DintIO) 或 Real32→Real (RealIO)
- 位打包字段 (状态/命令/报警) 用 DintIO 类型
- 浮点过程值用 RealIO 类型
- **DwordIO 不可用**
- DintIO 直接兼容 DInt, 无需 DWORD_TO_DINT 转换
- Release bit (Control Word 1, bit 3) 必须始终置 1

## 11. 同程序作用域规则

G20/G30/G40 等组的 Var.xlsx 和 Fun.xlsx 都属于同一程序 `NINH_3E8_2R1.LoescheMill`。

**含义:**
- 一个组定义的变量, 另一个组的 ST 代码可以直接访问
- 示例: G30 定义的 `N562_LQ1_LS48` 可被 G20 的 ST 代码直接引用
- 示例: G30 定义的 `N562_LQ1_T01_T_H` 可被其他需要该温度连锁的组引用

**注意: 同一变量不得在两个组的 Var.xlsx 中重复定义。**

## 12. ST 代码结构规范

### 12.1 文件头部注释模板

```pascal
(* ================================================================== *)
(* Gxx - <组名> (<英文组名>) - ST 代码部分                              *)
(* 项目: 越南F163 莱歇磨 LM46.2+2                                      *)
(* 程序: NINH_3E8_2R1.LoescheMill                                      *)
(* ================================================================== *)
(* 架构说明:                                                            *)
(*   - 功能块实例管脚连接在 FBD 中完成                                  *)
(*   - ST 代码只做:                                                     *)
(*     1. SignalInRealPar 结构体初始化                                  *)
(*     2. 布尔连锁逻辑                                                  *)
(* ================================================================== *)
(* 信号映射 (设计院编号 <-> 莱歇编号):                                  *)
(*   <变量名> <-> <莱歇编号>  (<描述>)                                  *)
(* ================================================================== *)
```

### 12.2 ST 代码执行顺序

```
1. SignalInRealPar 初始化 (阈值设定)
2. RS 触发器逻辑 (如有温度连锁)
3. process_lock 逻辑
4. start_lock + O2 逻辑
5. FBD 内容注释 (列出需在 FBD 中完成的管脚连接)
```

**ST 代码位置约束: 组初始化代码必须放在 GROUP/MOTOR1 调用之后、SignalInReal 调用之前。**

## 13. 常见错误与避坑指南

| 错误 | 原因 | 解决方案 |
|------|------|---------|
| Error 1340 编译错误 | Var.xlsx Initial Value 列使用结构体聚合语法 | 改在 ST 代码中逐个成员赋值 |
| 变量名冲突 | TOf/AlarmCond/SimpleEventDetector 实例放在 Var.xlsx | 放在 Fun.xlsx 中声明 |
| MOTOR1 O2 管脚不存在 | 误以为 MOTOR1 有 O2 管脚 | O2 是硬件 DO, 用 start_lock 管脚代替 |
| 温度误连锁 | 使用 GTH (纯比较) 而非 GTHStat | 连锁逻辑用 GTHStat (受 Enable 控制) |
| L 报警误触发 | 温度信号启用了 L/LL/LLL | 设置 EnableL/EnableLL/EnableLLL = FALSE |
| DP 数据类型错误 | 使用 DwordIO | 改用 DintIO (Int32) 或 RealIO (Real32) |
| 信号编号混淆 | 莱歇编号与设计院编号不同 | 在 Cement Mill IO List 中做映射 |
| start_lock 逻辑取反 | 误以为 true=允许 | true=锁定, H 报警时赋 TRUE |
| O2 逻辑取反 | 误以为 true=锁定 | O2 是硬件 DO, true=许可, 赋 NOT H |
| 同变量重复定义 | 两个组的 Var.xlsx 定义了同一变量 | 只在一个组中定义, 其他组直接引用 |
