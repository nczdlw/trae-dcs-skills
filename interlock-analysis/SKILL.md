# 连锁分析（PDF → 分组 FBD 管脚连接说明）

本 skill 由 F163 项目连锁分析任务跑通后收割。使用时配合 complex-task-decompose 的任务树机制执行：先按第二节的模板建任务树，再逐叶执行。

## 一、硬约束（不可违反）

1. **指定 PDF 为唯一基准**，ST 代码仅作参考
2. **逐页逐条落实**，细心，不允许偷工减料
3. **莱歇磨连锁信号不用 ST，全部用 FBD 做**
4. **一个功能块实例只能被一个程序使用**，不能同时出现在多个程序
5. **功能块设备名必须加注释**，注释内容 = 对应 Loesche 编号
6. **Var 表只放简单变量**（bool / dint / time / string 等），功能块实例放 Fun 表
7. **找不到实例依据时，告知用户并提供位置**，不猜测

## 三、检索目录规律（源文件通常在哪）

| 资料 | 位置模式 |
|------|----------|
| 连锁图（VP图） | `成品图-<日期>\05-EMSR\E-Doc\07_Interlocking diagram_VP\` |
| 启停顺序图 | `成品图-<日期>\05-EMSR\E-Doc\04_Start_Stop_Sequence_diagram\` |
| IO 点号表 | `更新点号表<版本>\*.xls`（以最新版为基准） |
| 参考 PDF（设定值查不到时用） | 其他项目连锁关系参考 PDF（记录页码） |
| master VAR/FUN 表 | 现场 Control Builder 工程导出目录 |

**设定值找不到的处理链**：基准 PDF → 参考 PDF（记页码）→ 仍无 → 列入「待莱歇确认表」。不得编造数值。

## 四、逐组叶任务的标准动作（每组重复同一模式）

1. 提取该组 VP 图连锁条件（含启停 / 联锁 / 保护）
2. 信号名 → VAR 变量名映射核对（对照点号表）
3. 生成该组 VAR / FUN 表
4. 生成该组 FBD 管脚连接说明（含图形化管脚连接图，仿 800XA 导出 FBD 图风格）
5. 登记设定值确认表（来源页码必填）

## 五、已知坑

1. VP 图设定值用符号引用（SP1/SP2/max1）无数值，必须查参考 PDF 落实，查不到列入待确认表
2. 通讯地址表"控制字 04+05"指 2 字节**字编号** 4 和 5，不是字节偏移 4-5
3. 锁变量（start_lock/process_lock）必须是 **bool** 而非 BoolIO；只有硬件 DI/DO（BoolIO）在 ST 中读取才需要 `.Value`
4. TON/TOF/TP 的 PT 参数用 Var 表的 TIME 变量（Initial 填 T#30S 等），不要内联 T# 字面量（会报 Error 1108/1117/1116）
5. 同系统多台电机共享一对锁变量前，先确认连锁条件**确实完全相同**
6. GROUP 功能块没有 G_start_lock / G_stop_lock 管脚，连锁在电机级（SMOTOR_PROV / MOTOR1）实现
7. ST 代码只含可执行逻辑，不含 VAR 声明（变量由导入表生成）
8. 报警用 AlarmCond（Signal, Message, Severity, SrcName, EnDetection）与 SimpleEventDetector（Signal, Message）；停止事件需手动边沿检测：`Signal := (NOT Running) AND prev_running`

## 六、复查阶段要求

- **逐页回读**：PDF 页 vs 产物逐条比对，不偷工减料
- **跨组一致性**：实例唯一性、共享变量冲突
- **按用户指定分组输出**各组详细 FBD 管脚连接说明；复查发现问题后，**重新**按分组输出
