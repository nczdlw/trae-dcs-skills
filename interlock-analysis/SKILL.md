# 连锁分析（PDF → 分组 FBD 管脚连接说明）

本 skill 由 F163 项目连锁分析任务跑通后收割。使用时配合 complex-task-decompose 的任务树机制执行：先按第二节的模板建任务树，再逐叶执行。

## 一、硬约束（不可违反）

> 规则带唯一编号；两条规则冲突时，编号小者胜出（借鉴 twincat-agent CRITICAL RULES 仲裁机制）。

1. **指定 PDF 为唯一基准**，ST 代码仅作参考
2. **逐页逐条落实**，细心，不允许偷工减料
3. **莱歇磨连锁信号不用 ST，全部用 FBD 做**
4. **一个功能块实例只能被一个程序使用**，不能同时出现在多个程序
5. **功能块设备名必须加注释**，注释内容 = 对应 Loesche 编号
6. **Var 表只放简单变量**（bool / dint / time / string 等），功能块实例放 Fun 表
7. **找不到实例依据时，告知用户并提供位置**，不猜测
8. **AI 生成/修改 FBD 连接说明后必须走第七节验证规则**，验证不过不算完成（借鉴 twincat-agent"改后必验，权威验证不可跳过"）
9. **用户问"为什么这样连锁"或描述问题时，交付物是分析结论**——不修改 FBD/表格，除非用户明确要求改（问原因 ≠ 授权改程序，借鉴 Gemini CLI 指令/询问二分 + Codex 请求类型四分类）
10. **用户口头纠正连锁条件时，先回基准 PDF 核对该页**——PDF 支持则改并记录，PDF 不支持则报告差异请用户裁决，不得直接按口头说法改（借鉴 Gemini 数据冲突裁决顺序：先核对，仍冲突则问）

## 三、检索目录规律（源文件通常在哪）

| 资料 | 位置模式 |
|------|----------|
| 连锁图（VP图） | `成品图-<日期>\05-EMSR\E-Doc\07_Interlocking diagram_VP\` |
| 启停顺序图 | `成品图-<日期>\05-EMSR\E-Doc\04_Start_Stop_Sequence_diagram\` |
| IO 点号表 | `更新点号表<版本>\*.xls`（以最新版为基准） |
| 参考 PDF（设定值查不到时用） | 其他项目连锁关系参考 PDF（记录页码） |
| master VAR/FUN 表 | 现场 Control Builder 工程导出目录 |

**设定值找不到的处理链**：基准 PDF → 参考 PDF（记页码）→ 仍无 → 列入「待莱歇确认表」。不得编造数值。

## 四、逐组叶任务的标准动作（每组重复同一模式）

1. 提取该组 VP 图连锁条件（含启停 / 联锁 / 保护）
2. 信号名 → VAR 变量名映射核对（对照点号表）
3. 生成该组 VAR / FUN 表
4. 生成该组 FBD 管脚连接说明（含图形化管脚连接图，仿 800XA 导出 FBD 图风格）
5. 登记设定值确认表（来源页码必填）

## 五、已知坑

1. VP 图设定值用符号引用（SP1/SP2/max1）无数值，必须查参考 PDF 落实，查不到列入待确认表
2. 通讯地址表"控制字 04+05"指 2 字节**字编号** 4 和 5，不是字节偏移 4-5
3. 锁变量（start_lock/process_lock）必须是 **bool** 而非 BoolIO；只有硬件 DI/DO（BoolIO）在 ST 中读取才需要 `.Value`
4. TON/TOF/TP 的 PT 参数用 Var 表的 TIME 变量（Initial 填 T#30S 等），不要内联 T# 字面量（会报 Error 1108/1117/1116）
5. 同系统多台电机共享一对锁变量前，先确认连锁条件**确实完全相同**
6. GROUP 功能块没有 G_start_lock / G_stop_lock 管脚，连锁在电机级（SMOTOR_PROV / MOTOR1）实现
7. ST 代码只含可执行逻辑，不含 VAR 声明（变量由导入表生成）
8. 报警用 AlarmCond（Signal, Message, Severity, SrcName, EnDetection）与 SimpleEventDetector（Signal, Message）；停止事件需手动边沿检测：`Signal := (NOT Running) AND prev_running`

## 六、复查阶段要求

- **逐页回读**：PDF 页 vs 产物逐条比对，不偷工减料
- **跨组一致性**：实例唯一性、共享变量冲突
- **FB 实例完整性检查**（借鉴 plc-st-review fb-instance 检查组，FBD 同样适用）：
  - 实例只被读输出、从未被调用（读 Q 永远拿到初值）
  - 同一实例在同一扫描周期被调用两次
  - 同一边沿触发器实例接了多个不同输入
  - 定时器 PT 赋了 T#0s、或读了 Q/ET 却没人驱动 IN
- **安全关键信号提级复核**（借鉴 plc-st-review 安全前缀机制）：连锁/安全关键信号（命名含 IL_/ES_/SIL_ 等前缀或用户指定清单）相关的任何改动，自动升为最高级复核——逐条对照基准 PDF 重新核对，不允许抽查
- **AI 改动后的回归核对**（借鉴 plc-st-review diff-based 检查思路）：管脚/变量签名变更是否同步了所有引用点；连锁常量/设定值是否被意外改动；变量类型变更是否影响读写点
- **测试化复核**：按第七节"测试用例反推"执行，断言结果记录统一用三段式 EXP（期望）/ACT（实际）/MSG（说明），数值比对带容差列
- **导入前检查（破坏性操作全链路）**：导入/覆盖 master VAR/FUN 表前必须已有备份且 L1-4 差异清单已过目；导入后报告新增/变更/冲突条数（前检查 → 执行 → 后告知，借鉴 Codex 破坏性操作协议）
- **按用户指定分组输出**各组详细 FBD 管脚连接说明；复查发现问题后，**重新**按分组输出

## 七、AI 辅助生成 FBD 的工程化规范（2026-09-14 GitHub 调研新增）

> 来源：hkoziolek/Spec2Control（控制叙述→FBD 的 LLM 工作流）、LLM-CodeGen-TestGen（测试用例生成）、TcUnit（断言格式）。调研详情见 knowledge/70-工具与工作方法/GitHub电气自动化项目调研报告。

### 7.1 标准化 FBD 文本表示（五段式）

AI 生成 FBD 管脚连接说明时，产物除图形化说明外，同时落一份**五段式纯文本表示**（机器可核对、可 diff、可转表）：

```
* Function Blocks *            类型 实例名（实例名=位号，如 SMOTOR_PROV EM301）
* Variables *                  数据类型 变量名（如 BOOL EM301_Start_Lock）
* Functions *                  类型 实例名（如 OR EM301_Interlock_OR）
* Data Connections *           源实例.管脚, 目标实例.管脚
* Parameter Data Connections * 字面量, 目标实例.管脚（如 T#30S, TON301.PT）
```

要点：连接一律写成"`源实例.管脚, 目标实例.管脚`"逗号对；每条连接可反向追溯到基准 PDF 页码（放同行注释或附表）。

### 7.2 库块规格表注入（防编造管脚名）

让 AI 写管脚连接前，先把涉及的库功能块规格以四列表内嵌进上下文（Direction, Pin Name, Type, Description）。800xA 常用块（电机/阀/PID/报警等）规格从工程导出或手册摘录，沉淀成可复用规格库文件。**禁止凭模型记忆写库块管脚名**——不确定就查规格表或 Control Builder 导出（呼应 twincat-agent 规则"外部对象禁止凭训练数据猜签名，必须查权威源"）。

### 7.3 生成硬规则（写进每次生成任务的约束）

- REAL/INT 模拟量信号不得直接进布尔逻辑门，先经比较器转布尔
- 报警/限值参数高低限必须成对出现（只有高限没有低限要显式说明原因）
- 同一布尔目标（inhibit/enable/lock）出现多路输入时，插入 OR 块合并，不允许并联悬空
- TON/TOF/TP 必须有明确 PT 值（Var 表 TIME 变量或参数连接），禁止留空
- 字面量不得直连设备控制输入；禁止 TRUE/FALSE 常量直接短接连锁链路
- 产物只允许五段式文本 + 管脚图两种格式，其余格式一律禁止；不加解释性文字（封闭枚举，"ANY OTHER FORMAT IS STRICTLY FORBIDDEN" 句式借鉴 Cursor）

### 7.4 测试用例反推复核（自洽性验证）

从提取出的连锁条件表反推测试用例，核对 FBD 连接说明的自洽性（不需真控制器）：

```
test1, state0, i, EM301_Start_Lock, TRUE      ← 喂条件
test1, state0, o, EM301.StartPermit, FALSE    ← 断言期望输出
test1, state1, i, EM301_Start_Lock, FALSE     ← 有状态逻辑展开多周期
test1, state1, o, EM301.StartPermit, TRUE
```

- 每条连锁条件至少一个用例；含延时/状态的逻辑按扫描周期展开 state 序列
- 含边界用例（限值临界点）；禁止构造超出数据类型边界的输入
- 断言失败按 EXP/ACT/MSG 三段式记录，数值比对带容差（借鉴 TcUnit AssertEquals 带 Delta）
