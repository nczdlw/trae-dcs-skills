### Spec2Control（LLM把控制叙述翻译成IEC 61131-3 FBD）

**1. 定位与规模**：多步LLM prompt链，把自然语言控制叙述转换为IEC 61131-3功能块图（FBD），输出PLCopen TC6 XML（v2.01），可直接用OpenPLC Editor打开（README.md）。Python实现，FastAPI后端+CLI双进程（src/spec2control_backend.py + src/spec2control_cli.py，USAGE_GUIDE.md"Option B"）；LLM走Azure OpenAI。40 stars / 9 forks。

**2. 仓库结构**（README.md Project Structure + API文件树）：
```
data/
  control-narratives/    # 输入：控制叙述（ammonium-nitrates、benzene-distillation、
                         #   coking-refinery、desalination等，每个含.md/.pdf/-spec.txt）
  BASIC_LIB/             # 12+个功能块规格
    specification/       # 每块一个txt：ANALOG_IN、BOOL_IN、DIGITAL_IN、MOTOR_ON_OFF、
                         #   MOTOR_2SPD、MOTOR_VSD、VALVE_ON_OFF、VALVE_ELECTRIC、
                         #   PID_BASIC、RATIO_CONTROL、SPLIT_RANGE、DUTY_STANDBY、VOTING_ANALOG
    src/                 # 对应的PLCopen XML实现
  prompt-sets/           # prompt链文件：contextgen.txt、openplc-fbd.txt
  fbd-baseline/          # 人工审核的基准FBD（10套装置，每章3个中间产物文件）
  fbd-GPT5-generated/    # GPT-5生成结果 + _evaluation-script-output（自动对比脚本输出）
src/
  spec2control_cli.py / spec2control_backend.py
  export_openplc.py      # 文本FBD→PLCopen XML转换器（含自动布局）
docs/                    # 两条prompt链文档 + PlantUML活动图
```

**3. 核心方法**：两段式prompt链（docs/Context-Generation-Prompts.md、docs/OpenPLC-FBD-Prompts.md）：

- **阶段一：上下文生成（3步）**，输出1_categorization.txt
  - 步1 sensors：识别传感器FB类型。prompt内**全文内嵌**候选FB管脚规格表（CSV四列：Direction,Pin Name,Type,Description），附硬规则："提到变送器→必含ANALOG_IN；报警开关→DIGITAL_IN；联锁报警→BOOL_IN"
  - 步2 actuators：识别执行器FB，规则："不确定阀门类型默认VALVE_ELECTRIC；不确定泵默认MOTOR_ON_OFF"
  - 步3 strategies：LLM给每个候选控制策略打概率，选定策略并输出**预期块间连接类型**（如 `ANALOG_IN.PV, PID_BASIC.PV`，含PID/串级/比值/投票/前馈/超驰/分程/备用切换8种策略模板）
- **阶段二：FBD生成（10步）**，输出2_control_logic.txt：
  1. FB识别（`类型 实例名`，实例名=位号如FT-101；不生成基础逻辑函数OR/AND）
  2. FB验证（交叉核对taglist，删多余）
  3. 主控制逻辑连接（**刻意排除联锁报警**；双输入函数不能留空输入）
  4. 联锁与报警逻辑（只用布尔函数；报警BOOL输出连Inhibit；**REAL不得进布尔逻辑**；字面量不得连DI_Raw；禁止literal TRUE直连inhibit）
  5. 参数配置初始（字面量→输入参数对；**高低限必须成对**）
  6. 参数细化
  7. 输出变量
  8. 综合验证（实例名一致性、无孤儿连接、**TON/TOF/TP必须有计时值**、合并进`* Data Connections *`）
  9. 附加规则检查（FunctionCategorization/NoProse/NoDI_RawParameterDataConnections）
  10. 布尔优化（**MultipleInputsOR：同一布尔目标（inhibit/enable/auto）多路输入时，插入新OR块合并**）

**FBD中间表示格式**（data/fbd-baseline/ammonium-nitrates/chapter_2/2_control_logic.txt实际文件）——五个带`*`标记的纯文本段落：
```
* Function Blocks *     类型 实例名（如 PID_BASIC FIC-102）
* Variables *           数据类型 变量名（如 REAL FT101_AmmoniaFlow_PV）
* Functions *           类型 实例名（如 OR AcidInhibit_OR）
* Data Connections *    源.管脚, 目标.管脚 （如 LT-104.High_Alarm, AcidInhibit_OR.IN1）
* Parameter Data Connections *  字面量, 目标.管脚 （如 90, LT-104.PV_High）
```
LLM只产出文本表示；由src/export_openplc.py确定性转换成PLCopen TC6 v2.01 XML+语义感知自动布局。

**验证手段**：①人工审核基准（fbd-baseline，每章0_cn_chapter.txt→1_categorization.txt→2_control_logic.txt分级中间产物）②自动评估脚本对比③experiment_results.xlsx统计④每步LLM对话留痕（prompt_chain_log.md）⑤OpenPLC Editor目检+Runtime仿真。

**prompt写法特点**：无角色设定；每步"Rules"硬规则清单；固定输出格式模板+"no explanations, no markdown"；步间占位符链式传递；无few-shot但内嵌完整库规格做知识注入。

### IO-AutoMapper（IO信号清单→库功能块映射）

**1. 定位**：把Excel IO清单条目映射到概念控制库LIB1功能块，IEEE ETFA 2025论文配套工具（README.md）。Python+LLM API；**300个信号约30分钟**。0 stars（新仓库）。

**2. 映射规则链**（io_automapper.py源码 + prompt_templates_LIB1/原文）：
1. **抽取**：按配置的列/行范围从Excel抽取（分小块chunk处理）
2. **信号解析**（identify_devices_task1.txt）：LLM输出JSON，每条含**rowNumber（Excel行号，用于回写原表）**/tag/system/deviceDescription
3. **信号分类**：判AnalogIn/AnalogOut/DigitalIn/DigitalOut
4. **设备→FB映射**：prompt内嵌LIB1五种FB+一句话描述（BinaryCtrl/TwoDirectionCtrl/VFDCtrl/ThreePositionCtrl/AnalogCtrl），规则"**同设备所有信号必须映射到同一个FB**"
5. **信号→FB参数映射**（按FB类型分5个模板）：prompt内嵌该FB完整参数表（name/type/direction/description四列），匹配依据="1) intended function 2) direction 3) type"，**无匹配输出n/a**
6. **输出**：原Excel追加3列；可选与`*_ground_truth.xlsx`基准对比生成`_check.txt`对账报告

**3. prompt模板四段式结构**：
```
*** Instruction ***（任务+硬规则，如"只输出FB名/参数名/n/a，不要解释"）
*** Available Function Blocks (name: description) ***（候选清单或完整参数表）
*** Output Format ***（输出格式示例）
*** I/O signal list to process ***（{header} + {content}占位符）
```

**4. 配置驱动处理异构表格**（src/config/defaults.py）：每类点号表一个配置对象（列名数组、信号tag列号、描述列号、**位号正则prefix/suffix模式**、起止行），不写死格式。

### plc-st-review（ST语义linter）

**1. 定位**：IEC 61131-3 ST的**确定性语义linter+PR评审机器人**，tree-sitter解析，**无LLM参与，发现完全可复现**（README.md）。TypeScript，**80个检查项**（src/engine/checks/下80个.ts文件逐一数过）+274个测试。14 stars，MIT许可。

**2. 检查项分类体系**（README.md + src/engine/checks/index.ts）：
四大类=21 diff-based + 59 static（static再分code-quality/style 31个、IEC 62443安全5个、单版本完整性23个）。docs/checks/按五子目录组织：code-quality/diff-based/**fb-instance**/security/static-integrity。

**3. 代表性检查条目**（全部核实过index.ts注册名）：
- **diff-based（21个，比before/after两版AST）**：SIGNATURE_CHANGED（POU签名变更）、CALL_SITE_OUTDATED（调用方没传新增必需参数）、TYPE_MISMATCH、ENUM_VALUE_ADDED/REMOVED（枚举增删值后CASE分支不匹配）、**TIMER_VALUE_CHANGED（PT变化按倍数分级：≥2x警告、≥10x错误，源码用log10比率）**、CONSTANT_VALUE_CHANGED（**名字带SAFETY_/INTERLOCK_/SIL_前缀自动提级为warn**）、COMPLEXITY_INCREASED（圈复杂度单PR涨超5）、DEAD_POU_INTRODUCED（新增POU无人调用）
- **FB-instance类（7个，最有PLC味）**：FB_INSTANCE_NEVER_CALLED（读T1.Q不调T1()永远拿初值；源码内置TON/TOF/TP/CTU/CTD/R_TRIG/F_TRIG/SR/RS已知类型集）、FB_INSTANCE_DOUBLE_CALL（一周期双调，PLCopen CP20）、EDGE_TRIG_REUSED（同一R_TRIG实例喂多个CLK）、TIMER_PT_ZERO、TIMER_NOT_DRIVEN、COUNTER_PV_ZERO、BISTABLE_DOMINANCE_MISMATCH（SR/RS选用与命名意图不符）
- **单版本完整性**：DIVISION_BY_ZERO、ARRAY_INDEX_OUT_OF_BOUNDS（字面量越界）、INFINITE_LOOP、UNINITIALIZED_VAR_USED、MULTI_WRITER_GLOBAL（一个全局变量多个PROGRAM写）
- **PLCopen对齐组**：DIRECT_ADDRESS_USED（%I0.0直访）、IF_WITHOUT_ELSE（L17）、FORBIDDEN_STATEMENT（GOTO/EXIT/CONTINUE，L10）、POU_NOT_COMMENTED（C2）、TOO_MANY_PARAMETERS（CP23，默认上限8）、TOO_MANY_GLOBALS_USED（CP18，默认10）、IMPLICIT_TYPE_CONVERSION（CP25）、TIME_EQUALITY（CP28）
- **IEC 62443安全组（5个）**：HARDCODED_CREDENTIALS（CR 1.5）、HARDCODED_NETWORK_ENDPOINT（SI-1）、UNVALIDATED_INPUT_USE（VAR_INPUT未校验就当数组下标/除数，CR 3.5）、DEBUG_PRAGMA_IN_PRODUCTION（SI-2）、PERSISTENT_PLAINTEXT_SECRET（CR 4.1）
- **团队配置驱动**：NAMING_CONVENTION、FORBIDDEN_SYMBOL（黑名单标识符，如已废弃全局变量名）

**4. 实现与工程实践**：
- 每个检查=独立模块导出`{category, defaultSeverity, run(ctx)}`，run是纯函数diff两张符号表
- 新增检查5步流程；文末**"何时不要写新检查"——变体优先给现有检查加配置旋钮，不新建类别**（"每多一个概念，用户就多一个要学/要关/要调的负担"）
- **检查文档五段式固定模板**：标题（大写检查名）/ Severity / Why it matters / Trigger（ST代码示例）/ The bot posts（输出样例）/ Fix（修复建议）
- **每条检查标注标准条款来源**（presets/plcopen.yml每行注释如`# L17 — Every IF shall have an ELSE clause.`；MISRA-C映射页三列表`check | MISRA-C rule | Intent`+诚实声明"意图级映射，非认证"+专列~45条"无标准等价的PLC领域特有检查"）
- CI用法：GitHub Action on pull_request paths ['**/*.st']，内联评论重跑更新不重复发；`--metrics`模式出圈复杂度/嵌套深度/死代码清单，`--format dot`出调用图SVG
- **BLUEPRINT.md第11节"Runbook for agents"**：21步有序脚手架清单，每步标注何时与用户确认，难以逆转操作（合并PR）前强制确认；**"Anti-patterns to refuse"反模式拒绝清单**（直推main、--no-verify跳钩子、提交密钥、"添加用户没要求的最佳实践"、permissions: write-all等7条）

## 三、oscat（PLC-lang）与 TcUnit

### PLC-lang/oscat（OSCAT Basic库可读ST源码）

**1. 定位与规模**：OSCAT Basic库ST源码（RuSTy编译器可编译的改编版：POINTER TO→REF_TO等少量语法修改，逻辑本体是OSCAT原库，README.md）。**实测统计（oscat.st全文605KB/30038行）：FUNCTION_BLOCK 171个 + FUNCTION 370个 ≈ 541个POU**。10 stars。OSCAT专有许可证。

**2. 库组织**：单文件顺序排列+每个POU头部`@PATH := '\Engineering\control'`分类元数据注解（CODESYS导出惯例）。分类两层结构（大类\子类）：String 75 / Mathematical 64 / Time&Date 55 / signal processing 43 / gate logic 38 / control 34 …

**3. 设计惯例**（oscat.st实测）：
- **家族前缀命名**：CTRL_（控制器：CTRL_PI/CTRL_PID/CTRL_PWM）、FT_（滤波：FT_PT1/FT_PT2/FT_INT/FT_DERIV）、GEN_（信号发生）、FF_（触发器）、ESR_（事件记录：ESR_COLLECT/ESR_MON_B8）；**数字后缀=通道数/深度**（INTERLOCK_4/FIFO_16/STACK_32/SEQUENCE_64）；**字母后缀=变体**（FT_PIW的W=窗口、FT_PIDWL的L=限幅）；**下划线开头=内部辅助块**（_RMP_B/_BUFFER_CLEAR，约定俗成的"私有"标记）
- **FB头注释四要素**：`version+日期 / programmer / tested by / 功能描述`（声明区后），`@END_DECLARATION`分隔声明与实现；**修订历史放代码体末尾**，格式"作者缩写+日期+rev版本+逐条改动"（FT_PT1修到rev 1.11，跨2007-2011；多人接力hm/ks/tb）
- **接口管脚惯例**：控制类全大写工艺缩写（ACT实际值/SET0设定值/MAN手动/RST复位/KP/TN/TV PID参数/LL/LH限幅/Y模拟输出/Q布尔输出/LIM限幅标志/TP单周期脉冲）；信号流类小写（in/T/K）；使能`E : BOOL`；模式`MODE : INT`（头注释逐值说明）；结构化数据走VAR_IN_OUT传引用
- **块内分层复用**：CTRL_PID = CTRL_IN + FT_PIDWL + CTRL_OUT组合，而非重复实现
- 反例警示：541个POU单文件30038行，检索靠元数据，维护成本高——工程应一个FB一个源文件+统一分类目录

### TcUnit（TwinCAT 3单元测试框架）

**1. 定位**：TwinCAT 3的xUnit型单元测试框架，PLC测试事实标准（README.md）。417 stars（委托方提供数字）。MIT许可。TcUnit-Verifier用TcUnit测试TcUnit自身（框架自举测试）。

**2. 测试组织**（docs/introduction-user-guide.md）：
```
PROGRAM PRG_TEST
    fbSum_Test : FB_Sum_Test;   ← 每个被测FB一个测试套件（镜像命名 FB_X → FB_X_Test）
    TcUnit.RUN();               ← 一行启动

FUNCTION_BLOCK FB_Sum_Test EXTENDS TcUnit.FB_TestSuite
    TwoPlusTwoEqualsFour();     ← 每个测试=一个自解释命名的方法

METHOD TwoPlusTwoEqualsFour
    TEST('TwoPlusTwoEqualsFour');       ← 标记开始
    Sum(one := 2, two := 2, result => Result);
    AssertEquals(Expected := ExpectedSum, Actual := Result,
                 Message := 'The calculation is not correct');
    TEST_FINISHED();                    ← 标记结束（允许跨多个PLC周期）
```
测试名前加`"disabled_"`即跳过（不改代码禁用用例）。

**3. 断言API**（FB_TestSuite.TcPOU + docs/api.md）：AssertTrue/AssertFalse；通用AssertEquals(ANY)；**类型化AssertEquals_\<TYPE\>覆盖22种IEC类型**；浮点AssertEquals_LREAL(Expected, Actual, **Delta**, Message)带容差；数组AssertArrayEquals_\<TYPE\>(可变长ARRAY[*])。**断言失败消息固定三段式**：`FAILED TEST '<TestInstancePath>', EXP: <期望值>, ACT: <实际值>, MSG: <用户消息>`。

**4. 结果输出**：三级数据模型ST_TestCaseResult{TestName/IsFailed/FailureMessage/NumberOfAsserts/Duration}→ST_TestSuiteResult→总表；xUnit XML报告供CI消费；容量参数集中带注释的参数表（GVL_Param_TcUnit：MaxNumberOfTestSuites=1000等）。
