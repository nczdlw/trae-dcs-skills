## 二、各来源核心发现（压缩版）

### LangGraph supervisor
- supervisor 无内置提示词，用户自定（团队成员名单+按领域路由规则）
- 拆解=工具调用参数里的自然语言任务描述，`transfer_to_<agent>` handoff 工具
- output_mode 双粒度回传：`last_message`（只回结论）/ `full_history`
- **无死循环防护、无重试**（反面教材）
- forward_message 原样转发 worker 末条消息，防转述失真

### AutoGen / Magentic-One（源码核实）
- 双循环：outer loop（重写 ledger/计划级）+ inner loop（逐步执行/进度级）
- Task Ledger 四节 FACTS：GIVEN OR VERIFIED / TO LOOK UP（注明去哪查）/ TO DERIVE / EDUCATED GUESSES
- Progress Ledger 每轮五键（各带 reason）：is_request_satisfied / is_in_loop / is_progress_being_made / next_speaker / instruction_or_question
- **stall 计数器**：无进展 +1、有进展 -1（可恢复），连续≥3 强制重入 outer loop 重规划
- **重规划仪式**：FACTS_UPDATE（猜测升级为已核实、必须新增至少一条新推测）→ PLAN_UPDATE（**先写失败根因**再出新计划）
- ledger 状态可全量序列化落盘（save_state/load_state）
- v0.4.4 更严：replan 上限 max_replans=3，超限终止

### CrewAI Hierarchical
- manager 强制无工具、只委派（带工具直接 raise）；委派描述原则"**对方对任务一无所知，须交代一切，解释而非引用**"
- 断点续作 `_get_execution_start_index`：从第一个无产出任务恢复，已完成只收集不重跑
- planning 模式计划要求：每步有 DONE 判据、**探索性查看不算完成、报错未恢复不算完成**、结尾 READY/NOT READY 门控
- expected_output 契约："MUST return the actual complete content, not a summary"
- 上下文超限自动五段摘要：概览/当前状态/重要发现/下一步/需保留上下文
- 死循环双保险：max_iter 超限→force_final_answer 强制收尾；重复输入检测
- Task 字段：description/expected_output/context（引用其他任务输出）/callback/output_file

### claude-flow（v2.7.47 + v3 源码核实）
- SPARC 五阶段（Specification→Pseudocode→Architecture→Refinement→Completion），**阶段间 Quality Gate 显式清单门禁**
- 编排器模板警告"过度拆解导致协调开销"
- namespace+TTL 记忆分层：artifacts(TTL=0 永久)/shared(1800s)/patterns(7天)/events(30天)
- SessionRecord 快照：跨会话打包 tasks+memory+agents，恢复结果可量化（n 任务/m 记忆）
- 任务状态机 pending|assigned|in_progress|completed|failed，状态变迁发领域事件（事件溯源）
- hook：任务完成自动 trainPatternsOnComplete 沉淀经验
- `.roo/` 目录为 v1 时代设计，当前版本无（如实注明）

### Anthropic 两篇博客
- **扩展上下文原则**：搜索本质是压缩，subagent 各自独立上下文探索，浓缩后回传 lead
- lead 先把**计划存入 Memory**（防 20 万 token 截断）——印证"任务树文件是唯一进度真相"
- **委托四要素**：objective / output format / 工具与信源指南 / 任务边界（与任务描述一体）
- **努力度分级**：简单事实 1 agent；比较类 2-4 个 subagent；复杂研究 10+ 且职责明确（防简单任务 spawn 50 个 subagent 的早期失败）
- 工件系统：subagent 输出直接写文件系统，只回传轻量引用，防多级传递失真（防"电话游戏"）
- **单线收敛**：subagent 互相频繁更新会互相干扰，结果统一回 lead 综合
- 失败处理：不重启、从出错位置恢复（durable execution）；LLM-as-judge 按 rubric 打分
- 评估最终状态而非逐轮路径

### BMAD-METHOD
- "Stateless Agents, Stateful Documents"（无状态智能体，有状态文档）
- story 文件：描述/验收标准 AC/Tasks 复选框/Dev Notes/Dev Agent Record/QA Results/Status 四态流转
- **写权限分区**：Dev 只许改 story 指定 section（勾选框/记录区），不许改 AC；QA 判据=测试全过+File List 完整+只改允许 section
- devLoadAlwaysFiles：开工必读文件清单

### OpenHands
- 子代理 Markdown+YAML frontmatter 文件化定义（name/description/tools/model）
- 委派=独立子会话独立上下文，结果单线回主 agent
- skills 分项目级常驻 + 触发词条件加载（常驻最小信息+按需加载细节）

### OpenAI Swarm
- handoff=函数返回另一个 Agent，控制流即数据；context_variables 共享黑板
- 失败把错误消息追加回对话让 agent 自恢复
- 已被 Agents SDK 取代，仅参考思想
