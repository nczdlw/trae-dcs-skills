# 01 目标与范围（阶段 0 交付物）

> 依据：《通用方法论迭代方案（红队评审与修订版）》第四节、第九节。
> 本文只定义边界；平台实测状态以《02-平台兼容矩阵.md》为唯一记录，本文不重复维护；任务进度以任务树为唯一记录。

## 一句话目标

给当前仓库维护者（娄哥）及其日常使用的 AI 工具（TRAE、WorkBuddy）一套**能用磁盘文件跨会话、跨模型恢复复杂任务的 AI 工程工作方法**——先证明它在 DCS 和非 DCS 任务里都能减少漏项和返工，再决定是否对外发展成通用技能库。

## 用户与任务

| 项 | 内容 |
|---|---|
| 首要用户 | 仓库维护者本人；工具 = TRAE(SOLO CN) + WorkBuddy（本阶段仅这两个为实测对象） |
| 典型任务 | DCS：连锁分析、VAR/FUN 核对、分组编程实施；非 DCS：长文档审阅、软件改造、研究综合 |
| 现有痛点 | ①上下文压缩后失忆→重跑→对话更长 ②任务状态存在对话里，换工具/模型接不上 ③skill 混装 TRAE 路径与 DCS 规则，换领域即失效 ④无验收/回滚/停止条件，项目自然扩张 |
| 非本阶段用户 | 外部开源用户——是后续假设，不是本阶段前提 |

## “通用”的口径（本仓库定义）

1. **领域资料可替换**：核心流程不按领域重写，只换输入资料与领域扩展（DCS 扩展单独成文）。
2. **平台行为分别实测**：安装、发现、触发、引用文件、脚本权限逐项记录；未测平台标“未验证”，不用“标准兼容”概括。
3. **纪律分级**：默认建议 / 满足条件时启用 / 领域插件规则；简单任务直接做，不建树、不强制 SVG、不强制入库。

## 成功标准（全部满足才可称“已验证的通用核心”）

1. 同一套核心方法用于一个 DCS 复杂任务和一个非 DCS 复杂任务，不改写核心步骤，只换领域资料或平台安装说明。
2. 至少在两个实际使用的 agent 工具中记录安装路径、技能发现、触发、引用文件和脚本权限的实测结果；未测平台明确标未验证。
3. 模拟会话中断后，只凭落盘任务状态和产物启动新会话；新会话能说对当前叶、下一步、未决问题和依据文件，不依赖旧聊天记录，不重做已完成工作。
4. 简单任务仍能直接完成，不因方法论强制创建任务树、SVG 或知识条目。
5. 每个资产有单一权威来源；没有未验证的镜像副本和互相覆盖的进度状态。

GitHub stars、仓库名称、支持平台数量都不是本阶段验收指标。

## 本阶段范围

**做：**

- 审核并瘦身 complex-task-decompose 的通用核心。
- 把 DCS 特有步骤与 TRAE 安装/知识库路径拆成可选扩展或单独说明。
- 保留既有恢复路径，做最小、可回滚的修改。
- 为真正使用的工具（TRAE、WorkBuddy）建立简短兼容性记录。
- 用真实任务做冷启动续接和跨领域试点。

**暂不做：**

- 不拆仓库、不改仓库名、不迁移全部目录。
- 不做 13 平台镜像、通用格式转换器或批量安装器。
- 不建大型能力域目录、MkDocs 站点、技能评分体系、商业付费包或全套 marketplace。
- 不为对齐第三方仓库强制采用 10-pattern、每技能多入口等模板。
- 不把每个任务产物自动收割为 skill/知识条目；入库以未来复用价值和用户授权为准。

## 仓库边界

- 本阶段 trae-dcs-skills 仍是 skill、模板与知识库的唯一源头（single source of truth）；不拆仓、不改名。
- 改动范围：complex-task-decompose 单一 skill（含新增 references）+ 新增 docs\通用方法论迭代\ + README 最小更新（门控后）；既有恢复路径保持可用。
- 知识库入库标准不变：以后会再查的才入。
