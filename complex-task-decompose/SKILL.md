# 复杂任务拆解（任务树 + 检索目录 + 状态外置）

## 一、为什么需要本流程

复杂任务的进度不能只活在对话里。有三个不随模型强弱变化的硬事实：

1. **会话语义必然结束**：会话会被关闭、上下文会被压缩、模型会被更换——对话记忆从设计上就是易失存储，再强的模型也逃不出这一条；
2. **工具必然更换**：同一个任务会在不同 agent 工具和模型间接力（换工具、换设备、换人接手），只有磁盘文件是各方都能读的共同载体；
3. **进度必须可审计**：做到哪一步、依据是什么、谁核对过——人要能看、git 能评、复盘能查。"说做了"不算数，磁盘产物才算。

**破解原理：状态外置。** 任务拆解、进度、检索路径、问题记录全部写入磁盘文件。**任务树文件是唯一进度真相，对话记忆只是缓存。**

附带收益：状态外置同时缓解上下文压缩造成的失忆与重跑——但这是附带效果，不是本流程存在的理由；规划能力更强的模型同样需要外置结构（它替不了会话结束和工具更换）。

## 二、触发条件（何时用）

满足任一条即使用本 skill：

1. 任务涉及 ≥3 个步骤，或 ≥2 个输入文件
2. 需要逐页 / 逐组 / 逐表批量处理
3. 会话可能跨多轮、中途可能触发压缩
4. 发现自己在重做之前做过的事（失忆信号，立即补建树）
5. 用户说"按任务树做 / 拆解任务"

已有对应任务类型 skill 时优先用那个，本 skill 是通用兜底。

**反向下限（防过度拆解）**：一条都不满足的简单任务直接做，不建树。拆解本身有协调开销——叶任务数要与交付物数量匹配，两步能做完的事不拆叶。

## 三、拆解规则

### 层级

| 层级 | 含义 | 划分依据 |
|------|------|----------|
| L0 根 | 复杂任务 | 一句话交付目标 |
| L1 阶段 | 里程碑 | 按交付物划分（不按时间） |
| L2 叶 | 简单任务 | 可独立执行的最小单元 |

**阶段门禁**：L1 阶段所有叶 ✅ 后，对照该阶段「交付物」做一次整体验收——显式过一遍判据清单，不是口头"看过了"——过关才进下一阶段。

### 叶任务准入四标准（不满足任一条就继续往下拆）

1. **单一输入源**：一个文件 / 一个页码范围 / 一张表
2. **单一输出物**：一个文件或一节内容
3. **可独立核对**：有明确"对了"的判据
4. **上下文自足**：只靠检索目录 + 该叶产物就能复查，不依赖对话历史。叶内禁用"见上文/如前所述"式引用——检验法：把该叶单独贴给新会话能直接做

## 四、任务状态记录（最少字段集）

任务树头部与续接快照只记以下内容，够恢复现场即可；只有输入定位或复核需要时才加字段：

| 字段 | 内容 |
|---|---|
| 目标 | 一句话交付物 |
| 已核对完成项 | 状态 = ✅ 的叶编号（部分完成不算完成） |
| 当前项 | 正在执行或中断的叶 |
| 下一项 | 下一个 ⬜ 叶编号 |
| 阻塞 | ❌ 叶及卡点，无则 0 |
| 产物路径 | 各叶输出的绝对路径 |

进度行格式（供脚本解析）：`> 当前进度：<n/N ✅｜下一步: <叶编号>｜未决: <数>（<说明>）`

## 五、开工与恢复动作

0. **接续会话（任务树已存在时）**：先读任务树 → 向用户复述定位（进度行 n/N、下一叶编号、未决数）→ 经确认后续做下一叶，不重建树
1. **查经验知识库（可选）**：若用户提供或配置了知识库位置，先读其索引，按分类/标签定位同类任务经验，登记进任务树检索目录；未提供则跳过，**不猜默认机器路径**
2. 在约定的工程目录（默认 `AI任务管理\<任务名>\`，用户另有约定从其约定）下创建 `任务树.md`
3. 同目录生成 `任务树导图.svg`（可选能力，格式规范见 `references/svg-mindmap.md`；本任务不启用则跳过）
4. 向用户展示树结构，确认拆解合理后再动手执行第一个叶任务

## 六、任务树模板（复制即用）

```markdown
# 任务树：<任务名>

> 目标: <一句话交付物>
> 唯一基准: <基准文件路径 + 版本>
> 本文件是唯一进度真相，对话记忆仅为缓存。每轮开始先读本文件。
> 状态图例: ⬜未开始 / 🔶进行中 / ✅完成已核对 / ❌有问题待复查
> 建树: <日期> | 最近更新: <日期> | 导图: 同目录 任务树导图.svg（每次更新同步重写）
> 当前进度: <n/N ✅｜下一步: <叶编号>｜未决: <数>（每完成一叶更新此行；会话收尾必核对，提交按用户授权）
> 已知事实: <已核实的关键事实>（可选行，任务涉及大量待确认信息时用：已核实 / 待查 / 推测分区）

## L1-1 <阶段名>（交付物: <该阶段产出什么>）

- [ ] L1-1.1 <简单任务名>
  - 输入: <绝对路径 + 页码/工作表/行号>
  - 输出: <产物文件路径>
  - 核对: <怎么算对了>
  - 状态: ⬜
  - 问题: -

## 问题复查区

| 日期 | 叶编号 | 问题描述 | 按检索目录复查结果 | 结论 |
|------|--------|----------|--------------------|------|
```

说明：
- 叶任务编号 = 阶段.序号（如 L1-3.2），全树唯一；复查区、接续指令引用叶任务一律用编号
- 复选框勾选 = 该叶已执行完；「状态」字段 = 核对状态（✅ 才算真正关闭）。两者需保持一致
- 进度行 n/N 只计「状态 = ✅」的叶；只执行未核对的叶不计入——部分完成不算完成
- 颗粒度判据：AI 拿到该叶输入后能不提问直接完成；还要问 = 拆得不够，一个编号装多件事 = 拆得太细
- 「核对」判据要可判且排除假完成：跑完没核对不算 ✅、探索性看一眼不算 ✅、报错未恢复不算 ✅

## 七、执行规则（R1-R11，硬性要求）

- **R1 开工先建树**：复杂任务必须先产出任务树文件再动手，不允许边做边想
- **R2 每轮重读树**：每个子任务开始前重读任务树.md，以文件为准，不信对话回忆
- **R3 即时落盘**：每完成一个叶任务，先自检三问——①核对判据满足了吗 ②是否在重复劳动 ③下一步叶编号明确吗——再更新勾选、状态、树头进度行 + 保存产物；本任务启用导图时同步重写。绝不攒到最后
- **R4 一次一叶**：默认一轮只处理一个叶任务，保持单轮上下文小；批处理型叶（同构逐页/逐表）可在单轮内连续执行，但每完成一叶立即落盘
- **R5 复查走目录**：出问题按检索目录直查源文件定位，再改
- **R6 收割按需**：全部叶 ✅ 且用户验收后，才考虑把任务类型流程提炼为 skill、产物经验入库；是否收割以未来复用价值和用户授权为准，不自动执行（技能落地位置与知识库入库流程见扩展）
- **R7 卡叶升级与重试上限**：同一叶连续 2 轮无实质进展，或单叶重试达 3 次，立即停——标 ❌ 进问题复查区、输出当前最佳结论并**升级用户决策**，禁止静默自循环重试；重拆该叶前必须先写失败根因
- **R8 写权限分区**：执行时只允许改勾选、「状态」「问题」字段和树头进度行；「输入/输出/核对」是任务定义，要改 = 走重拆（先记录原因再改），禁止静默改
- **R9 单写者**：任务树只由主会话（编排者）维护；子代理/并行会话不直接写树、不做 git 操作，结果一律回传主会话核对后统一落盘
- **R10 反模式拒绝清单**：①未经用户确认做难以逆转的操作（强推、删基准文件、覆盖工程导出物）②跳过强制核对步骤 ③添加用户没要求的"最佳实践"、与任务无关的改动和过度工程 ④为凑结果编造查证不到的数据/来源
- **R11 假设浮出水面**：叶任务执行中做了影响任务方向的假设，必须记入问题复查区并计入未决数；推进性假设允许，但改变任务方向的假设必须明说上下文、假设内容、理由

## 八、检索目录（每个叶任务必填）

| 要素 | 内容 | 作用 |
|------|------|------|
| 输入 | 源文件**绝对路径** + 精确定位 | 出问题后直达源头 |
| 输出 | 产物文件路径 | 复查时找到被检对象 |
| 核对 | 验证方法（抽查方式、比对基准） | 判断"对了"的客观标准 |
| 状态 | ⬜ / 🔶 / ✅ / ❌ | 恢复现场、定位断点 |

**产物防缩水**：叶任务产物必须原文落盘为文件；复查与后续引用一律读产物原文，不读、不写"转述版"。

## 九、出问题后的复查流程

1. 读任务树「问题复查区」，定位出问题的叶任务
2. 按该叶「输入」直查源文件（精确到页码 / 工作表 / 行号）
3. 与该叶「输出」产物比对，定位差异
4. 修改后按该叶「核对」方法重新验证
5. 结论回写问题复查区表格

**禁止凭对话记忆直接改——必须先按检索目录回源头确认。**

## 十、可选能力（按任务风险启用，不默认强加）

| 能力 | 启用条件 | 规范位置 |
|---|---|---|
| SVG 思维导图 | 任务跨多轮、叶数多、需要向他人展示全局进度时 | `references/svg-mindmap.md` |
| 并行子代理 | 叶任务量大且互不依赖（调研类、批量同构）；派发指令须自包含四要素（目标/输出格式/范围边界/禁止事项），结果单线回收（R9） | 本表即规范 |
| 收割为 skill / 经验入库 | 全部 ✅ + 用户验收 + 判断有复用价值 + 用户授权 | 技能落地见 `references/platform-adapters.md`；DCS 知识库入库见 `references/dcs-extension.md` |
