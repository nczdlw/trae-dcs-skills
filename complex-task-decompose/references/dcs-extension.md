# DCS 领域扩展（complex-task-decompose 可选扩展）

> 本文件是 complex-task-decompose 的**领域扩展**：只在 DCS 工程环境下使用本技能时加载。
> 通用核心（SKILL.md）不含本文件任何内容；换其他领域时写各自的扩展文件，不动核心。
> 适用环境：trae-dcs-skills 仓库（本机 `D:\.AI\GITHUB\trae-dcs-skills`，clone 目标任意目录）+ 其 knowledge/ 经验知识库 + DCS 项目工作流。

## 一、何时读本文件

- 在 DCS 工程（800xA / 莱歇磨 / 水泥等行业变量与功能块工作）中按任务树执行复杂任务；
- 或任务需要检索历史经验、任务完成后要入库。

## 二、经验知识库检索（开工动作第 1 条的领域版）

1. 读 `knowledge\INDEX.md`（唯一入口），按分类/标签定位同类任务经验；
2. 读条目正文，把相关条目登记进任务树「检索目录」的相关经验来源区；
3. 分类速查：00-规范 / 10-系统与工程配置 / 20-DP通讯与设备功能块 / 30-莱歇磨与连锁分析 / 40-变量与功能块规范 / 50-实施与分组程序 / 60-核对复查与整改 / 70-工具与工作方法 / 90-项目档案；
4. 查 F163 编程规则从 `knowledge\90-项目档案\F163_800xA编程规则总纲.md` 入手（唯一现行规则入口）；
5. 检索不到就写"未检索到"，**不得编造条目或来源**。

## 三、经验入库（R6 收割的第二产出，领域版）

全部叶 ✅ + 用户验收 + 判断有复用价值 + 用户授权后，才执行：

1. 把产物 MD 复制到 `knowledge\` 对应分类（分类定义见 `knowledge\00-规范\分类规范.md`）；
2. 按 `knowledge\00-规范\条目模板.md` 补 frontmatter（title/date/project/type/device(可空)/tags/summary/source），正文原样保留不改写；
3. `knowledge\INDEX.md` 对应分类加一行（摘要取自 summary），同轮更新；
4. git 提交并推送——**属外部副作用，必须用户明确授权后执行**；授权前只落盘不提交。

**入库标准（TIL 原则）**：以后会再查的才入。会话中间产物、一次性过程记录不入。项目档案不默认可公开。

## 四、DCS 项目级衔接

- 开新 DCS 项目：复制 `templates\DCS项目全流程总纲.md`（P1~P6 阶段框架）作项目总树，单任务再建各自任务树；
- 领域专用技能优先：连锁分析类任务用 `interlock-analysis` 技能（PDF→FBD 管脚连接说明），本技能只提供任务树机制兜底；
- 收割的新 skill 落到本仓库技能目录（唯一源头），提交推送后再按平台复制——平台安装位置见 `references/platform-adapters.md`。

## 五、与通用核心的边界

- 本文件出现的一切路径、仓库结构、Git 流程都是 DCS 环境事实，不是通用规则；
- 通用核心引用本文件时只写"见 references/dcs-extension.md"，不把本文件内容抄进核心。
