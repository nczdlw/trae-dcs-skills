# DCS 自动编程调试框架：报告模板

> 用途：框架各环节（P4 编程 / P5 核对 / 调试阶段）产出的报告统一格式，保证可复查、可追溯。
> 配套模块：`dcsaf/ir/diff.py`（diff_points/diff_logic）、`dcsaf/adapters/ab800xa.py`
> （parse_800xa_export）、`dcsaf/tools/quick_response.py`（detect_change/regenerate_affected/byte_order_fix）、
> `dcsaf/tools/simulator.py`（verify_interlocks）。
> 五类报告：点表一致性报告、逻辑生成差异报告、下装回读报告、仿真结果报告、调试变更报告。
> 每类报告含：报告名称、用途、主要章节、必填字段。

---

## 1. 点表一致性报告

| 项 | 内容 |
|---|---|
| 报告名称 | 点表一致性报告（Point Table Consistency Report） |
| 用途 | P5 核对阶段：比对两份点号表/点位 IR 的双向一致性（基准点号表 vs 程序引用），定位未引用点与未定义引用，防止"点表改了程序没跟上"。适用于 IO 点全覆盖核对（总纲 P5）与点表版本差异核对。 |

主要章节：

1. 报告信息（项目、日期、报告编号、核对人）
2. 比对范围与基准（基准点号表版本、比对对象来源、比对方法：diff_points 或逐列核对）
3. 差异概览（新增/删除/变更点数统计）
4. 差异明细（逐条：位号、字段、旧值→新值，可直接引用 diff 输出）
5. 未引用点清单（点表有、程序引用无）
6. 未定义引用清单（程序引用有、点表无）
7. 结论与处理建议

必填字段：

- 项目名
- 基准点号表版本（文件路径 + 版本日期）
- 比对对象来源（如各组 VAR 表 / 现场导出）
- 未引用点数与清单
- 未定义引用点数与清单
- 结论（一致 / 有差异待处理 + 差异处理责任人）

## 2. 逻辑生成差异报告

| 项 | 内容 |
|---|---|
| 报告名称 | 逻辑生成差异报告（Logic Generation Diff Report） |
| 用途 | 记录"设计 IR 逻辑 → 生成产物（FUN 表/回读 IR）"之间的差异，区分"可接受的信息丢失（表列结构所限）"与"需要修复的逻辑差异"。适用于 generate_fun_excel 后回读 diff_logic、或 AI 生成逻辑与人工示例的比对。 |

主要章节：

1. 报告信息（项目、日期、报告编号）
2. 版本对（设计 IR 版本号 → 生成/回读版本号）
3. 差异概览（diff_logic 的 新增/删除/变更 条目统计）
4. 差异明细（逐条：路径、旧值、新值）
5. 已知信息丢失说明（如 FUN 表不含管脚/参数列，Fb.pins 整体不回读——属设计内丢失，非 bug）
6. 需修复项清单（丢失信息之外的真实差异，附修复动作）
7. 结论（可接受 / 需修复后重出）

必填字段：

- 项目名
- 设计 IR 版本号与路径
- 生成产物版本号与路径
- 差异条目数（增/删/改）
- 已知信息丢失字段说明
- 需修复项清单
- 结论

## 3. 下装回读报告

| 项 | 内容 |
|---|---|
| 报告名称 | 下装回读报告（Download & Readback Report） |
| 用途 | 组态导入 800xA 后，用 parse_800xa_export 回读现场/导出表，与原始 IR 比对，确认下装内容与设计一致；含 DP 字节序核对（byte_order_fix），用于调试阶段"导入后数值错乱"类问题的定位。 |

主要章节：

1. 报告信息（项目、日期、控制器/组名、下装时间）
2. 回读范围（VAR/FUN 导出文件路径、回读工具与时间戳）
3. 点位差异明细（diff_points：位号、signal_type 方向还原、字段丢失）
4. 逻辑差异明细（diff_logic：实例、类型）
5. 字节序核对结果（byte_order_fix 处理清单 + 警告项，逐点标注"生成侧应用方式 / 回读校验方式"）
6. 差异归因说明（哪些是表列结构导致的已知丢失，哪些需现场处置）
7. 结论与现场处置建议

必填字段：

- 项目名与控制器/组名
- 导出文件路径（VAR/FUN）
- 回读时间
- 差异条目数（点位/逻辑）
- 字节序处理清单与警告数
- 结论（下装一致 / 需现场处置项清单）

## 4. 仿真结果报告

| 项 | 内容 |
|---|---|
| 报告名称 | 仿真结果报告（Simulation Result Report） |
| 用途 | 记录仿真调试回环结果：probe_simulator_800xa 探测、inject_test_signals 注入、verify_interlocks 连锁逐条验证（实测或静态推导）。用于连锁逻辑交付前验证（总纲 P5 测试化核对扩展）。 |

主要章节：

1. 报告信息（项目、日期、仿真服务器端点、连接状态）
2. 仿真场景（场景名、涉及的连锁类型 STAITL/OPITL/PRTITL/PSTITL/PQSTOP、输入条件）
3. 注入信号表（位号、强制值、注入时间）
4. 断言结果表（EXP 期望 / ACT 实测 / MSG 说明，数值带容差；未实测项标注"未实测（无仿真器连接），静态推导"）
5. 边界用例（条件临界值用例）
6. 失败项处理结论（逐条）
7. 结论与遗留项

必填字段：

- 项目名
- 仿真场景名
- 输入信号表（至少一条注入）
- 断言结果表（EXP/ACT/MSG 三段式）
- 通过率（通过用例数/总用例数）
- 失败项处理结论
- 结论

## 5. 调试变更报告

| 项 | 内容 |
|---|---|
| 报告名称 | 调试变更报告（Commissioning Change Report） |
| 用途 | 调试/整改阶段点表变更的快速响应记录：detect_change 变更检测 + regenerate_affected 重建说明 + byte_order_fix 字节序处理，用于"现场改点 → 影响分析 → 组态重生成"的留痕与复核。 |

主要章节：

1. 报告信息（项目、日期、变更来源（现场/设计）、责任人）
2. 变更概览（新旧点表版本号；changed_points 清单：增/删/改）
3. 变更明细（diff 原始条目，含字节序修正等字段级变化）
4. 受影响功能块（affected_fbs 清单 + 影响原因：引用哪个变更点）
5. 组态重建说明（regenerate_affected 输出：新管脚连接、新参数、需人工在 FBD 编辑器确认的连线）
6. 字节序处理与警告（byte_order_fix：处理清单 + none 警告项，标注"推断/待核实"）
7. 处置建议与结论（哪些可直接重生成、哪些需人工确认后导入）

必填字段：

- 项目名
- 新旧版本号（点表 IR）
- 变更点位清单
- 受影响 FB 清单
- 重建说明（每实例：连接/参数/人工确认数）
- 字节序警告数
- 结论
