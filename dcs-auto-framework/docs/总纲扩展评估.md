# 总纲扩展评估：三平台框架章节是否并入 DCS 项目全流程总纲

> 评估日期：2026-10-08
> 评估对象：/workspace/templates/DCS项目全流程总纲.md（P1-P6，800xA 单平台项目级任务树模板）
> 被评估内容：把三平台 DCS 自动编程调试框架（dcs-auto-framework）章节并入总纲
> 说明：本文件只给出评估结论，未修改总纲文件（按任务约束，总纲保持现状）。

## 结论

**不建议**把三平台框架章节并入现有总纲。

## 理由

1. **定位不同**：现有总纲是 800xA 单平台项目流程模板（P1 资料搜集→P6 交付，面向 F163 这类
   具体项目逐阶段挂子树执行）；框架是跨平台（800xA/PCS7/Freelance）的工具层，两者一个是
   "项目怎么走"、一个是"用什么工具做"，合并会混淆职责边界。

2. **内容形态不同**：框架是持续演进的代码工程（IR/Adapter/工具链随任务迭代），并入总纲会把
   总纲从"项目流程模板"变成"工具文档"，总纲读者（逐组推进时按阶段定位任务）会被工具内容干扰。

3. **体积与效率**：框架章节（目录结构 + T1-T9 模块清单 + 待核实项）会显著增大总纲体积；
   总纲作为项目级任务树模板，应保持轻量，方便逐组推进时快速定位阶段/任务。

4. **已有承载**：框架信息已有独立入口——框架根目录 README + knowledge 条目
   （70-工具与工作方法/DCS自动编程调试框架说明.md），检索路径已建立，重复并入收益低。

5. **可选的衔接方式**：如未来需要，在总纲 P4/P5 阶段加一行"可选工具引用"链接到
   knowledge 框架条目即可（如"连锁/编程环节可参考 dcs-auto-framework 工具链"），
   不必整章并入，保持总纲与工具文档解耦。

## 后续建议（不在本任务范围）

- 若总纲未来要扩为多平台项目模板（如新增 PCS7/Freelance 项目），再单独评估是否新增
  "三平台工具"独立章节或独立总纲，届时以本项目评估结论为依据。
